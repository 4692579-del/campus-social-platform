# 学校认证申请：部署与验收

后续更新：管理员审核代码已接入，升级配置和完整闭环验收见 [学校认证审核部署与验收](学校认证审核部署与验收.md)。下文保留申请阶段的部署说明。

本次只完成学校认证申请的提交、本人查询和重复提交保护。管理员审核列表、材料查看、通过/驳回操作将在下一小步开发，现在提交后会保持“审核中”，不会自动变成学生用户。

## 本次实现

- 入口：“我的 → 申请学校认证”，未登录账号先登录，管理员不展示申请入口。
- 表单：学校全称、姓名、学号、一张 JPG/PNG 认证材料，以及资料用途确认。学校暂由用户填写全称，不预置虚假的学校目录，也不在申请阶段分配 schoolId。
- 图片：选择后尝试压缩，限制在 1MB 以内；在页面内存中读取 Base64，再由云函数上传到私有材料目录。不新增第三方依赖，避免客户端直接上传后还可以覆盖/删除审核材料。
- 状态：待审核时只读；支持展示已认证/驳回结果，并预留驳回重提能力，但本次没有提供审核接口。
- 权限：云函数使用真实微信 OpenID 定位用户，只返回本人申请。姓名、学号和材料不加入公开个人资料，接口不接受客户端指定审核状态、审核人或角色。

## 部署顺序

必须先配置私有存储，再开启上传。上传开关默认关闭，避免材料落入原本公开读取的存储规则。

1. 在当前云环境 `campus-social-dev-d3dmcsfefdcae4` 中，创建数据库集合 `certification_applications`。
2. 把新集合的数据权限设为“仅管理员可读写”，或自定义规则 `{ "read": false, "write": false }`。已有 `users` 集合继续保持同样的权限。这里的管理员是云平台权限，不是业务字段 role。
3. 打开云开发控制台“存储 → 权限设置 → 自定义安全规则”，查看现有规则。参考同目录的 `certification-storage.rules.json` 设置：公开读取 `avatars/`，只允许创建者写头像；保留原 QuickStart 使用的 `my-photo-时间戳.png`、`my-photo.png`、`code.png` 示例读取，其余路径不向客户端开放。
4. 如果环境还有自行添加的其他公开目录，需要在规则中逐项保留，不要不加检查地替换。**不要公开 `certification-proofs/`，也不要把所有图片都设为公开读取。** 云函数服务端 SDK 不受客户端存储规则限制，仍可以上传材料。
5. 规则生效约需 1—3 分钟。用开发者工具控制台对一个不存在的 `certification-proofs/permission-check.png` 尝试 `wx.cloud.uploadFile`，`filePath` 选合成测试图片；应当提示权限拒绝，确认没有新增文件。也要确认已有头像仍能显示和正常更换。不要用真实证件做权限测试。
6. 右键 `cloudfunctions/userService`，选择“创建并部署：云端安装依赖”。本次没有新依赖，不需要部署 QuickStart 云函数。
7. 在云函数 `userService` 的配置中设置环境变量 `CERTIFICATION_UPLOAD_ENABLED=true`。只在完成私有规则检查后开启；未开启时提交返回“认证材料存储尚未配置，请稍后再试”，查询功能不受该开关影响。若修改配置要求重启/部署，按控制台提示保存生效。材料上传比普通资料查询耗时，可把函数超时设为 20 秒后验收。
8. 重新编译小程序，进入“我的 → 申请学校认证”。真机测试需重新预览或更新体验版代码。

规则语法依据：[CloudBase 云存储安全规则](https://docs.cloudbase.net/storage/security-rules)。本地 JSON 文件只是配置参考，不会自动更新云端规则。当前开发工具账号若只有小程序开发权限，没有云环境配置权限，需要由有云环境权限的账号完成上述配置。

## 云端数据

集合 `certification_applications` 每个账号保留一份最新申请，主键为 `cert_用户ID`。确定性主键配合数据库事务，保证并发请求不会产生多条待审核申请。

| 字段 | 用途 |
| --- | --- |
| userId | 申请人账号 ID，由云函数填写 |
| schoolName / realName / studentNumber | 学校全称、姓名、学号；学号按字符串保留开头的 0 |
| proofFileID | 私有材料云文件 ID，不向普通查询接口返回 |
| status | pending / approved / rejected |
| requestId / fingerprint | 用于识别同一份请求的重试，不作为用户身份依据 |
| revision | 最新申请版本，首次为 1；驳回后重提递增 |
| createdAt / submittedAt / updatedAt | 首次创建、本次提交、最后更新时间，均由服务端生成 |
| reviewerId / reviewedAt / rejectionReason | 后续审核使用；新提交时为空 |

提交时在一个事务中写入申请和 `users.certificationStatus=pending`；不改变 role、schoolId、昵称和头像。网络重试不会覆盖审核中的申请。事务用法参考 [CloudBase 数据库事务](https://docs.cloudbase.net/database/transaction) 和 [微信云函数 SDK 类型定义](https://github.com/wechat-miniprogram/wx-server-sdk/blob/master/index.d.ts)。

材料上传和数据库事务不属于同一个原子操作。极少数并发/写入失败会留下未被引用的私有文件；当前不自动删除，以免超时请求其实已提交成功却误删材料。后续可按数据库引用核对清理，不能直接删除整个材料目录。

本人查询只返回姓名、学号、学校、状态、提交时间、驳回原因及“已提交材料”标记。客户端没有批量读取申请或按其他用户 ID 查询的接口；管理员查看材料将在下一小步通过受保护的云函数实现。

## 验收顺序

使用合成测试资料和不含真实个人信息的示例图片。已提交申请会保持待审核，不需要为了继续演示而直接改数据库角色。

| 操作 | 预期结果 |
| --- | --- |
| 普通账号进入认证页 | 显示表单；未登录时提示先登录 |
| 输入空学校、非法学号，或不选择图片/不确认用途 | 显示具体提示，不提交 |
| 取消选图 | 不报失败，也不清除之前选好的图片 |
| 超过限制的图片 | 尝试压缩，仍超过 1MB 则提示重新选择 |
| 正常提交 | 显示“审核中”，学校、姓名、学号、材料标记和时间正确 |
| 查看数据库 | 仅一份当前申请；users 为 pending，role 仍为 user、schoolId 仍为空 |
| 返回我的页面 | 显示待审核，再进入能看到之前申请 |
| 重新编译或退出后重新登录 | 申请仍存在，不依赖本地缓存 |
| 待审核时再次提交/并发提交 | 不新增或覆盖申请，不再次升级身份 |
| 另一个普通账号调用 getCertification 并传入申请人的 userId | 只能得到另一个账号自己的申请或 null |
| 管理员进入申请页 | 显示无需认证，不提供申请表单 |
| 未配置上传开关或规则权限错误 | 不显示提交成功，可保留草稿后重试 |
| 云函数/网络出错 | 显示错误；提交超时后会查询状态，已保存则展示审核中 |

本阶段无法在小程序中通过或驳回申请，管理员工作台仍显示下一阶段开放，这是本次范围。
