# 全网热搜部署与验收

## 部署

1. 在当前绑定的云环境中新建 `hotboard_cache` 集合，权限设为“仅管理员可读写”（自定义规则见 `hotboard-cache.rules.json`）。小程序只调用云函数，不直接访问此集合。各平台使用固定文档主键，不需要额外索引。
2. 上传整个新云函数 `cloudfunctions/hotboard`，选择“上传并部署：云端安装依赖”，执行超时设为至少 20 秒。无需改动现有 `userService`。
3. 如使用 UAPI Key，只在 **hotboard 云函数环境变量** 设置 `UAPI_API_KEY`，值填 Key 本身，不带 `Bearer ` 前缀。客户端、`app.js`、`project.config.json` 和 Git 仓库均不保存 Key。未配置 Key 时按官方文档使用访客模式；配置了 Key 后，鉴权失败不会改用访客身份重试。
4. 重新编译小程序，打开底部“搜索”。本次只接入热搜展示及站内搜索，不启用测试账号自动发帖，也不新增定时任务。

## 接口契约与缓存

- 指定文档：[UAPI 热榜原始文档](https://uapis.cn/docs/api-reference/get-misc-hotboard.md)，[文档页面](https://uapis.cn/docs/api-reference/get-misc-hotboard)。固定 `GET https://uapis.cn/api/v1/misc/hotboard?type=平台`，仅使用实时榜默认模式。全网热榜使用 `weibo`、`zhihu`、`bilibili`、`baidu`，Cui 热榜使用 `toutiao`，不传历史时间、历史关键词或仅用于历史搜索的 `limit`。
- 按文档读取顶层 `type`、`update_time`、`list` 及条目的 `index`、`title`。`index` 原样作为榜单排名，不按当前显示位置重新编号；不使用猜测的 `data`、`updatetime` 等其他格式。第三方封面、原始链接及 `extra` 不返回前端，不跟随外链、不抓取其他网站。
- 可选鉴权使用 `Authorization: Bearer Key` 请求头。固定 HTTPS 域名，不接收客户端 URL、Key 或强制绕过缓存参数，不跟随 HTTP 重定向；总请求超时 8 秒、响应上限 1 MiB。日志不输出请求头、Key 或上游原始错误正文。
- 每个平台持久化缓存 5 分钟。单实例合并请求，跨实例用 20 秒事务租约防止同时拉取；过期持有者不能覆盖新数据。缓存新鲜时不请求 UAPI。失败释放租约，并使用短时冷却防止持续消耗调用额度。
- 上游失败且仍有 24 小时内实际获取的缓存时，保留榜单并明确显示“更新暂不可用，显示上次获取的榜单”；没有可用缓存时显示真实错误及重试入口，不填充示例或模拟词条。缺少集合时明确提示缓存尚未配置。
- 前端仅保存本次运行内的公共榜单缓存及合并请求，不含账号信息。通常复用 1 分钟，过期时间不超过服务端缓存；已标记过期榜单只复用 15 秒，便于恢复后重查。返回页面优先展示真实缓存，后台更新不覆盖关键词或作者胶囊。

## 页面行为

- 搜索框下显示“全网热搜”，“Cui热榜 / 全网热榜 / 校园热榜”三栏采用首页同款文字与蓝色指示条，默认显示 Cui 热榜，在宣传片下方展示今日头条热搜。校园热榜为空白页。全网热榜箭头展开四个平台菜单，每条热搜一行，初始最多展示15条，底部“显示更多”每次从真实缓存追加10条，全部显示后明确提示；不伪造上游分页或补齐词条。标签栏从首帧通过 CSS sticky 固定在搜索框下方，滚动区顶部间距为20rpx，关闭弹性回弹与下拉刷新；底栏和发布按钮随滚动方向缩为80%或恢复100%。
- 主搜索页点击搜索框进入副搜索页。副搜索页通过键盘提交，右侧取消返回主搜索页，搜索记录只在副搜索页本地保存和展示。点击热搜词仍直接进入站内搜索结果。
- 点击词条进入现有独立搜索结果页，按标题搜索全站广场动态；若此前带 `@ID` 作者胶囊，此入口会移除作者限定。标题超过现有搜索长度上限时只使用前 100 个 Unicode 码点查询。没有匹配动态时使用现有真实空结果页面，不生成或补造帖子。
- `update_time` 为来源 UTC 时间，页面换算北京时间显示。这个时间与本地获取/缓存时间分开，不能把旧来源榜单标成刚刚更新。部分平台返回的来源时间可能较早，页面如实展示；所谓实时是接口当前可提供的最新榜单，不保证各个平台同时更新。
- 快速切平台、进入结果页、切后台及卸载后，迟到响应不能覆盖当前平台或旧页面。重试保留已有真实词条；首次加载显示加载状态，真实空列表才展示“该平台暂无热搜”。

## 验收

1. 依次切微博、知乎、B站、百度，核对 UAPI 原始接口同一快照中的标题、排名和来源更新时间。榜单数量以接口实际返回为准，不补齐固定总数。
2. 上下滚动完整热榜，检查原始排名；切换平台后返回复用真实缓存。确认标签栏吸顶、底栏缩放只有80%和100%，已有搜索草稿不被榜单更新覆盖。
3. 点一个真实热搜词，检查站内动态查询；从个人主页带作者胶囊进入时，点击热搜按全站查询。没有相关动态时正确显示空结果，不外跳上游 URL。
4. 模拟网络失败、401/402/429、无效 JSON、超时及缓存集合未建立，分别检查明确错误和重试。已有缓存时保留并标记，不能报成功或伪造空榜。恢复后重新获取真实数据。
5. 查看云端集合，确认每个平台独立缓存，频繁切页不会持续请求 UAPI；并发请求不重复拉取，旧租约结果不覆盖新榜单。检查前端包和云函数返回值不含 API Key。

UAPI 自身额度、限速及上游缓存以 [官方常见问题](https://uapis.cn/docs/api-reference/faq) 为准；配置 Key 不等于无限额度。本地测试使用隔离的契约样本，应用运行时只显示 UAPI 真实响应或此前真实响应的缓存。
