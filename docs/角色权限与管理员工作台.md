# 角色权限与管理员工作台

后续更新：学校认证审核已接入，当前部署与验收请参照 [学校认证审核部署与验收](学校认证审核部署与验收.md)。下文保留角色基础阶段的说明。

本阶段修正用户角色、增加管理员入口和基础工作台，并在云函数中校验管理权限。学校认证申请、认证审核、举报处理和封禁操作尚未开放，工作台不展示虚假的待处理数量。

## 部署顺序

1. 确认 `users` 集合仍设置为“仅管理员可读写”，或安全规则为 `{ "read": false, "write": false }`。这里的“管理员”指云平台的访问权限，与业务字段 `role: admin` 是不同概念。小程序用户不能直接修改自己的角色。
2. 确认已初始化的管理员记录 `u_83a6c615e460d79e5899a266a6909a29` 在 `users` 中的 `role` 为字符串 `admin`，`status` 为 `active`。代码不硬编码这个账号，也没有公开的“设为管理员”接口。
3. 在微信开发者工具中右键 `cloudfunctions/userService`，选择“上传/创建并部署：云端安装依赖”。本阶段复用现有云函数，不需要新增云函数或数据库集合，也不需要重新部署 QuickStart。
4. 部署完成后重新编译；真机体验使用最新代码包，需要重新预览或更新体验版。
5. 两个账号分别进入“我的”，等待云端资料读取完成；也可以退出后重新登录。

必须先更新云函数再验收客户端。旧云函数不返回 `role` 时，客户端显示“身份待同步”并隐藏管理入口；这时应检查部署状态，不要通过前端写死角色解决。

## 三种角色

| role | 业务身份 | 生效条件 |
| --- | --- | --- |
| user | 普通用户 | 默认注册身份，不具有学生或管理权限 |
| student | 学生用户 | 同时满足认证 approved 且 schoolId 非空 |
| admin | 管理员 | 受控地在云端授予，不要求学生认证 |

所有可用身份均要求 `status` 为 `active`。`banned` 等其他状态不能登录、恢复资料、保存资料或访问工作台。未知角色会被拒绝。角色为 student 但认证或学校不完整时，接口只按普通用户返回，不给予学生权限；不会自动把普通用户升级成学生。

`role`、`certificationStatus`、`schoolId` 和 `status` 均不允许通过个人资料接口修改。前端只控制入口展示，管理接口每次都依据云端 OpenID 查到的用户记录重新鉴权；传入别人的用户 ID、OpenID 或 role 没有授权作用。

## 已有数据的兼容处理

第一阶段曾将新账号默认设为 `student`，但其 `certificationStatus` 为 `unverified` 且 `schoolId` 为空。新云函数在该用户登录、恢复资料等请求时，会将这个明确组合的旧记录修正为 `user`，保留账号 ID、OpenID、昵称、头像及创建时间，只更新角色和更新时间。

修正使用包含原角色、认证状态和学校的条件更新，再重新读取记录。因此，即使管理员授权与普通登录同时发生，也不会把刚授予的 admin 覆盖掉。admin 账号、已认证学生和其他数据组合不会被这条兼容规则批量修改。

该处理是按当前用户请求触发的，不是自动扫描全部用户。其他认证状态与角色不一致的数据需由维护者核查，后续认证模块会使用事务维护一致性。

## 双账号验收

| 操作 | 预期结果 |
| --- | --- |
| 原普通账号登录 | 显示“普通用户”“未认证”，没有管理入口；旧记录 role 修正为 user |
| 新管理员账号登录 | 显示“管理员”，出现“管理工作台”，不再展示学生认证提示 |
| 管理员进入工作台 | 显示该账号昵称、管理员身份和访问验证已通过 |
| 管理员修改昵称头像后重新登录 | 资料正常保留，角色仍为 admin |
| 普通账号直接打开 pages/admin/index | 显示仅管理员可访问，不显示工作台数据 |
| 未登录直接进入管理页面 | 提示先登录，不自动建立账号 |
| 将管理员 role 暂改 user，再重新进入工作台或下拉刷新 | 云端拒绝；恢复 admin 后再次进入可用 |
| 将测试管理员 status 暂改 banned 后重试 | 云端拒绝且本地登录标记被清除；测试完成后恢复 active |
| 云函数调用失败后重新进入工作台 | 显示重试，不保留上一次的工作台内容 |

本阶段的认证审核卡片仅说明下一阶段功能，不提供审核按钮，不读取尚不存在的认证申请集合。学校认证闭环通过后，再验证真正的学生升级与审核操作。
