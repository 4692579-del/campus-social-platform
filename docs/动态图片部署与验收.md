# 动态图片部署与验收

本次包含云端和前端改动，不能只编译小程序。无需新增集合；旧文字动态无需迁移。

## 部署

1. 在小程序当前绑定的同一云环境，进入「云开发 → 存储 → 权限设置 → 自定义安全规则」，使用 [square-images-storage.rules.json](square-images-storage.rules.json) 的完整内容保存。它保留项目原有头像及演示图片规则，加入图片暂存与公开成品两类目录；认证材料继续禁止客户端直接访问。如果云端另有自己新增的目录规则，应合并后保存，不要丢失已有规则。
2. 在「数据库 → square_posts → 索引管理」增加一个**非唯一**复合索引，索引名称填写 `square_album_by_author`。字段按以下顺序添加到这**一个**索引中：

   | 字段 | 排序 |
   | --- | --- |
   | authorId | 升序 |
   | scope | 升序 |
   | status | 升序 |
   | hasImages | 升序 |
   | sortKey | 降序 |

   等索引创建完成。原有动态、本人动态、评论索引全部保留。
3. 右键整个 `cloudfunctions/userService`，选择「上传并部署：云端安装依赖」，包括新增 `square-images.js`、更新的 `square.js` 和 `index.js`。云函数运行超时建议设为 **60 秒**，供九张图片的校验和成品保存使用；原有文字校验权限保持不变。
4. 重新编译小程序，然后真机预览。开发者工具无法代替手机相机及相册权限验收。

## 数据与权限

- 点击发布面板的图片图标，可选「从相册选择」或「拍照」，单条动态最多 9 张，可分次添加、移除、预览。大图先压缩，支持 JPG、PNG、WebP，压缩后单张最大 5MB。可以发布图文，也可以只发布图片。
- 客户端把原件上传至 `square-uploads/{当前用户ID}/`。此目录仅文件创建者可读写，不向其他账号公开。
- `userService` 校验当前账号、环境、数量、目录、文件字节类型和大小，再复制为 `square-media/{用户ID}/{动态ID}/` 下的公开成品。客户端不能写入成品目录，避免已发动态图片被直接替换。内容哈希构成成品文件名，同一请求重试不会重复建帖。没有实现图像内容安全审查；已有文字安全检查继续执行。
- 数据库存储 `images`、`imageSources`、`hasImages`；对外只返回成品 `images`。新索引供相册查询使用，集合仍保持「仅管理员可读写」。
- 相册从当前账号已发布且有图片的动态中分页读取，只展示图片。首页、个人动态和详情使用同一横向图片轮播，左右滑动不触发详情跳转，点击图片进入微信大图预览。
- 发布成功后立即同步列表和相册缓存；删除动态后不再出现在相册。删除动态不物理清理已公开成品文件，原有链接可能仍可访问；后续如需彻底回收，可增加专门的云端清理流程。
- 主动点击右上角草稿保存或退出确认中的“保存为草稿”才上传并保存图片草稿，使用云文件 ID 而非临时本地路径，重新打开仍能恢复。选图/上传/发布失败保留编辑内容与已经上传的结果供重试。取消未保存内容显示三选项弹窗；选择“不保存”或清空文字和全部图片后取消，删除当前账号草稿及已知暂存文件。发布成功后也会尽力清理暂存文件。未完成或废弃的上传、替换草稿及失败成品可能留下孤立文件，不自动删除其他文件。
- 贴纸、GIF、回复区图片按钮仍未开放；动态设置中的回复/查看范围仍仅为本地选择。内容声明已随动态真实保存，带图时显示在图片下方，具体见[动态广场部署与验收](动态广场部署与验收.md)的内容声明章节。

权限规则使用 CloudBase 的路径与文件创建者条件，服务端管理身份不受客户端规则限制，见 [CloudBase 存储安全规则](https://docs.cloudbase.net/storage/security-rules)。保存规则后可能需要 1—3 分钟生效。

## 验收

1. 未认证普通用户选择两张照片、输入文字并发布；首页立即出现真实图文动态，重启并刷新后仍在。左右滑动图片、点击放大并切换大图。
2. 分次选择至 9 张，第 10 张不能加入；移除一张后可补充。测试相机拍照、相册取消、拒绝权限、大尺寸照片和纯图片发布。
3. 进入个人主页「相册」，仅看到该账号已发图片；删除图文动态、刷新相册，图片消失。发布纯文字不增加相册图片。
4. 图片主动保存草稿，关闭再打开仍可查看；清空文字和图片后取消，再次打开为空。切换账号不能恢复上个账号图片。
5. 断网或让上传失败：正文和选图保留，不提示成功；恢复网络重试，已完成上传不重复上传，同一次发布不重复建帖。
6. 两个账号交叉检查：不能把另一个账号原件用于发布，不能通过客户端写入公开成品目录，认证材料保持私有。

本地自动检查运行 `node --test`，使用合成数据，不连接真实云环境或发布测试动态。微信原生 WXML/WXSS 编译另外校验；真机权限、实际网络上传及云端规则生效仍需以上验收。

## 真机返回后仅剩图片的兼容调整

根据“发布图片 → 首页菜单 → 个人主页 → 返回首页”时图片仍显示、文字及互动栏缺失的截图与代码，按前端合成层恢复异常排查，尚未取得故障手机的运行日志，不能确认具体微信或系统版本的根因。

- 单张图片使用普通图片节点，不再为每张单图动态创建轮播。图片容器固定原有高度，灰色边框和点击大图保留。
- 多图轮播在页面隐藏及显示时保留原节点、图片资源与 `imageIndex`，不再在轮播和静态图之间切换。先前“隐藏时释放轮播”的兼容方案会导致预览或切页返回时重建图片，现已移除；仍忽略隐藏、卸载和越界的轮播回调。
- 首页菜单推动及板块切换使用位置过渡，移除滚动区祖先的 `transform` 和长期 `will-change`，保留原有平移效果。此项避免增强滚动、轮播和父级变换持续叠加；不改数据库或云端存储。
- 首页相同的缓存结果不重复替换整组卡片，真实内容、时间和计数变化仍正常更新，不清空列表或强制联网重载。
- 图片列表单独保存在卡片内部，仅图片 ID 或顺序发生实际变化时更新；时间、点赞等普通资料更新不会重复写入图片源。单图和多图的显示分支仅由真实图片数量决定。

真机验证需重新进入调试以加载新前端：分别发布单图、九图、纯文字动态，反复通过侧栏进入个人主页再返回；检查昵称、正文、灰边、互动栏、列表位置和多图当前页是否保留，再验证下拉刷新、校园圈切换、点赞及大图预览。自动测试覆盖状态与数据路径，不能替代故障手机上的绘制验证。
