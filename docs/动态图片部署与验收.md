# 动态图片部署与验收

本次包含云端和前端改动，不能只编译小程序。无需新增集合；旧文字动态无需迁移。

## 部署

1. 在小程序当前绑定的同一云环境，进入「云开发 → 存储 → 权限设置 → 自定义安全规则」，使用 [square-images-storage.rules.json](square-images-storage.rules.json) 的完整内容保存。它保留项目原有头像及演示图片规则，加入图片暂存与公开成品两类目录；认证材料继续禁止客户端直接访问。如果云端另有自己新增的目录规则，应合并后保存，不要丢失已有规则。
2. 在「数据库 → square_posts → 索引管理」增加一个**非唯一**复合索引，索引名称填写 `square_album_by_author`。字段按以下顺序添加到这**一个**索引中：

   | 字段 | 排序 |
   | --- | --- |
   | authorId | 升序 |
   | scope | 升序 |
   | status | 升序 |
   | hasImages | 升序 |
   | sortKey | 降序 |

   等索引创建完成。原有动态、本人动态、评论索引全部保留。
3. 右键整个 `cloudfunctions/userService`，选择「上传并部署：云端安装依赖」，包括新增 `square-images.js`、更新的 `square.js` 和 `index.js`。云函数运行环境使用 Node.js 16 或更高版本，使用「云端安装依赖」安装随 npm 包提供的 `@ffmpeg/core`，默认无需原生可执行文件，也不需要在云端连接 GitHub 下载二进制。如果已配置原生 FFmpeg 层，可将 `SQUARE_FFMPEG_PATH` 指向层中的绝对可执行路径。该路径无法启动时自动使用随包转码器。云函数运行超时设为 **60 秒**，转码建议使用 **512 MB 或以上内存**，供媒体校验和成品保存使用；原有文字校验权限保持不变。
4. 重新编译小程序，然后真机预览。开发者工具无法代替手机相机及相册权限验收。

## 数据与权限

- 点击发布面板的图片图标，可选「从相册选择」或「拍照」，新发动态图片和视频合计最多 3 个，可分次添加、移除、预览。大图先压缩，支持 JPG、PNG、WebP，压缩后单张最大 5MB。可以发布图文，也可以只发布图片。
- 发布面板的相册支持混选图片和视频。支持系统相册能选出的视频，也可从聊天文件导入 MOV、MP4、MKV、WebM、AVI 等视频。较大的文件先由手机尝试压缩，云端按文件内容识别。小于或等于 20 MiB 的兼容 H.264 MP4 及 1080p 以内的 8-bit Main HEVC MP4 可直接保存。小于或等于 20 MiB 的兼容 H.264 / AAC MOV 优先由 `mediabunny` 保留画质和声音换为 MP4 容器，需要重新编码时再使用 FFmpeg，保留原画面方向，不自动截断视频。云端暂存原件上限 100 MiB，压缩成品上限 48 MiB，超出或超过云函数处理期限时保留编辑内容并提示原因。单项沿用宽高比布局，多项按选择顺序左右滑动，点击视频封面打开微信原生预览。旧动态继续展示原媒体，超过 3 个媒体的旧草稿可缩减后发布。个人相册和小萃识图仅读取动态中的照片。视频做格式校验，正文继续通过既有内容审核。
- 视频发布请求中断时，小程序按当前账号及原提交标识确认云端是否已保存。已保存时显示成功，未确认时保留正文和附件，供原请求重试。若出现云函数调度错误，请在云开发控制台查看同一时间的 `userService` 调用记录、运行内存和超时时间。
- 客户端把原件上传至 `square-uploads/{当前用户ID}/`。此目录仅文件创建者可读写，不向其他账号公开。
- `userService` 校验当前账号、环境、数量、目录、文件字节类型和大小，再复制为 `square-media/{用户ID}/{动态ID}/` 下的公开成品。客户端不能写入成品目录，避免已发动态图片被直接替换。内容哈希构成成品文件名，同一请求重试不会重复建帖。没有实现图像内容安全审查；已有文字安全检查继续执行。
- 数据库存储 `images`、`imageSources`、`hasImages`；对外只返回成品 `images`。新索引供相册查询使用，集合仍保持「仅管理员可读写」。
- 相册从当前账号已发布且有图片的动态中分页读取，只展示图片。首页、个人动态和详情使用同一横向图片轮播，左右滑动不触发详情跳转，点击图片进入微信大图预览。
- 发布成功后立即同步列表和相册缓存；删除动态后不再出现在相册。删除动态不物理清理已公开成品文件，原有链接可能仍可访问；后续如需彻底回收，可增加专门的云端清理流程。
- 主动点击右上角草稿保存或退出确认中的“保存为草稿”才上传并保存图片草稿，使用云文件 ID 而非临时本地路径，重新打开仍能恢复。选图/上传/发布失败保留编辑内容与已经上传的结果供重试。取消未保存内容显示三选项弹窗；选择“不保存”或清空文字和全部图片后取消，删除当前账号草稿及已知暂存文件。发布成功后也会尽力清理暂存文件。未完成或废弃的上传、替换草稿及失败成品可能留下孤立文件，不自动删除其他文件。
- 贴纸、GIF仍未开放；回复区图片现已支持，见文末评论图片章节；动态设置中的回复/查看范围仍仅为本地选择。内容声明已随动态真实保存，带图时显示在图片下方，具体见[动态广场部署与验收](动态广场部署与验收.md)的内容声明章节。

权限规则使用 CloudBase 的路径与文件创建者条件，服务端管理身份不受客户端规则限制，见 [CloudBase 存储安全规则](https://docs.cloudbase.net/storage/security-rules)。保存规则后可能需要 1—3 分钟生效。

## 验收

1. 未认证普通用户选择两张照片、输入文字并发布；首页立即出现真实图文动态，重启并刷新后仍在。左右滑动图片、点击放大并切换大图。
2. 分次选择至 3 个媒体，第 4 个不能加入。移除一项后可补充。测试相机拍照、相册取消、拒绝权限、大尺寸照片和纯图片发布。
3. 进入个人主页「相册」，仅看到该账号已发图片；删除图文动态、刷新相册，图片消失。发布纯文字不增加相册图片。
4. 图片主动保存草稿，关闭再打开仍可查看；清空文字和图片后取消，再次打开为空。切换账号不能恢复上个账号图片。
5. 断网或让上传失败：正文和选图保留，不提示成功；恢复网络重试，已完成上传不重复上传，同一次发布不重复建帖。
6. 两个账号交叉检查：不能把另一个账号原件用于发布，不能通过客户端写入公开成品目录，认证材料保持私有。

本地自动检查运行 `node --test`，使用合成数据，不连接真实云环境或发布测试动态。微信原生 WXML/WXSS 编译另外校验；真机权限、实际网络上传及云端规则生效仍需以上验收。

## 真机返回后仅剩图片的兼容调整

根据“发布图片 → 首页菜单 → 个人主页 → 返回首页”时图片仍显示、文字及互动栏缺失的截图与代码，按前端合成层恢复异常排查，尚未取得故障手机的运行日志，不能确认具体微信或系统版本的根因。

- 单张图片使用普通图片节点，不再为每张单图动态创建轮播。图片容器固定原有高度，灰色边框和点击大图保留。
- 多图轮播在页面隐藏及显示时保留原节点、图片资源与 `imageIndex`，不再在轮播和静态图之间切换。先前“隐藏时释放轮播”的兼容方案会导致预览或切页返回时重建图片，现已移除；仍忽略隐藏、卸载和越界的轮播回调。
- 首页菜单推动及板块切换使用位置过渡，移除滚动区祖先的 `transform` 和长期 `will-change`，保留原有平移效果。此项避免增强滚动、轮播和父级变换持续叠加；不改数据库或云端存储。
- 首页相同的缓存结果不重复替换整组卡片，真实内容、时间和计数变化仍正常更新，不清空列表或强制联网重载。
- 图片列表单独保存在卡片内部，仅图片 ID 或顺序发生实际变化时更新；时间、点赞等普通资料更新不会重复写入图片源。单图和多图的显示分支仅由真实图片数量决定。

真机验证需重新进入调试以加载新前端：分别发布单图、三图、纯文字动态并查看历史九图动态，反复通过侧栏进入个人主页再返回；检查昵称、正文、灰边、互动栏、列表位置和多图当前页是否保留，再验证下拉刷新、校园圈切换、点赞及大图预览。自动测试覆盖状态与数据路径，不能替代故障手机上的绘制验证。


## 评论区图片发送（最新）

- 一级评论及楼中回复支持图文或仅图片发送，每次最多3张。输入框图片按钮可选相册或拍照；沿用图片压缩、JPG/PNG/WebP格式、单张5MB检查，选择后上传私有原件。待发送图片显示在输入框上方，可移除及点击大图，上传中有状态提示，失败保留预览供重试；贴纸/GIF继续占位。
- 预览统一160rpx正方形、18rpx圆角；待发送、发送中和正式评论共用样式，固定三列靠左紧凑排列，图间距12rpx，每张都有1rpx灰色细边框，一或两张仍保持原大小，不滑动或上下堆叠。问问小萃与三个工具图标在空输入时统一居中显示，输入文字后一起隐藏（包括图片按钮），保留原生输入/键盘约定；图片不计入50字文字上限。
- 云端校验真实账号、当前环境及本人square-uploads原件，最多3张，复用square-images字节检查与服务端上传成品流程。评论图片落在square-media/作者/评论ID/序号-摘要路径，对客户端仅公开只读；imageSources仅在管理员可读数据库中用于幂等，不返回前端。评论与楼中回复均保存images，阅读/删除/举报/折叠/缓存沿用已有权限及数量事务；举报快照包含图片。
- 相册仍只查询本人已发布square_posts，评论图不加入个人相册，也不自动保存到手机相册。成功发送、移除和关闭面板时尽力清理暂存原件；与动态图片一样，删除评论不会物理回收已公开成品。
- 图片发送过程中立即收键盘，显示“发送中”本地行；云端成功后替换正式记录，失败恢复原文、图片、回复目标、小萃选择及原提交ID。旧账号、卸载面板或迟到响应不能恢复旧输入。关闭/账号变更不保存评论草稿。
- 问问小萃可结合动态至多9张及本条评论至多3张图片回答，两组按来源编号分别处理；仍须通过按钮选择askAI标记。任意一图解析失败不丢图降级，输出审核与小时/每日额度沿用已有规则。接入依据：[DeepSeek官方图文接口与多图限制](https://api-docs.deepseek.com/guides/vision/)。

部署：上传并部署完整cloudfunctions/userService（云端安装依赖），包括更新的square.js、ai-images.js、square-ai.js、deepseek.js、index.js与ai-errors.js，执行超时60秒；重新编译小程序。无需新增集合、索引或密钥，已有square-images-storage.rules.json继续适用，不放开客户端写square-media。尚未配置动态图片规则的环境，仍须先应用本文原有规则。

验收：相册/拍照选择1、2、3张及补图/移除；输入文字后工具栏隐藏，清空后恢复；只发图、带文字、一级及楼中评论，确认前后预览同尺寸单行布局；上传失败/发送失败重试不丢图、不重复评论；其他账号/环境文件与第4张图片被拒绝；个人相册不增加评论图；动态9图加评论3图问小萃可分别理解来源；读取及生成期间删除评论、删动态、封禁或换账号不产生迟到回答。自动测试使用合成图片及SDK模拟，原生相册权限、拍照、大图预览和线上模型仍需真机验收。

原生相册/相机及大图预览可能触发页面隐藏：active-comments在此期间保留组件与本地选图，返回恢复原评论位置，普通导航离页及账号变更仍按原逻辑清理。真机验收时应特别往返相册、相机、预览，确认评论面板不消失且已选图片仍在。


## 时间线单图自适应与多图carousel

首页、个人主页和动态详情复用square-post的同一套图片布局。单图读取image组件真实load尺寸，按原比例完整显示；最大高度840rpx，超长竖图同步收窄，保留原画面。新图首次还未知尺寸时以4:3预留占位，解码后只修正布局一次；已加载图片以最多256条内存尺寸缓存复用，不另行取临时URL或下载图片，不存原图及私人资料。

多图使用原生swiper横向滑动，右侧露出下一项44rpx，每项有12rpx间隔；每张单独20rpx圆角、1rpx灰边，整组首图决定360—640rpx高度。多图列表预览为等比裁切，点击后原生预览显示完整原图；没有自动播放、循环播放或宫格。去掉白色圆点，保留轻量数字位置提示。切到最后一张时右侧保留滑动组件的留白，不伪造下一张。

点赞、评论数和时间变化不重写图片资源；预览、隐藏及返回保留原组件和当前页。仅图片集合真正变化才更新列表；非首图load及滑动不改整组高度，避免浏览过程中反复跳变。旧图无需迁移数据；详情使用其更宽的内容区域。评论区的160rpx三图预览不改。

部署：仅重新编译小程序，无需部署云函数或修改数据库。验收16:9横图、1:1方图、3:4竖图及超长图；两图、三图和九图的右侧露出与滑动；纵向滚动不误开详情，点图可按原顺序看全图；滑到第二/最后一张后往返预览及个人主页位置不复位；点赞/时间刷新不闪图，图片失败不破坏正文、声明及互动区。自动化覆盖几何计算、尺寸缓存、迟到事件和节点保留；原生手势/真实图片尺寸与EXIF表现仍需真机验收。

## 个人主页视频

部署完整 `cloudfunctions/userService` 后重新编译小程序。视频列表复用 `square_posts` 的 `posts_by_author` 索引，按 `sortKey` 倒序分页，直接读取已有动态的 `media` 数组。数据无需迁移。视频和封面使用当前云环境 `square-media/` 下的公开成品。

从本人和访客主页的相册下拉菜单进入「视频」。检查同一动态的多个视频分别显示、封面点击后原位播放、正文和留白点击后进入原动态。验收切换标签或离开主页后停止播放，并检查下拉刷新、分页以及切回相册时原有图片仍可查看。没有封面的视频显示灰底播放按钮。
