# 动态广场部署与验收

## 本轮范围与最新参与规则

- 游客可以浏览公开广场动态与评论，发布和互动需要微信登录。点击卡片正文可进入动态详情页，游客也可浏览。
- 普通登录用户无需学校认证，即可发布文字动态、点赞和回复。广场发布入口固定为 `square`，没有校园圈或其他板块选项。
- 校园圈、跑腿和集市的加入与业务参与保留学校认证限制；这些业务、关注流、私信和好友功能后续开发。本轮不修改或假装实现它们。
- 当前支持最多 150 字、9 张图片的动态（文字或图片至少一种），动态字数包含空格、换行和标点，前后端按 Unicode 码点计数；1—300 字文字回复保持不变。发布栏圆环蓝色填充，剩余不超过 20 字时变红、平滑放大并显示剩余字数，输入和粘贴最多录入前 150 字，达到上限时在圆环上方显示灰底气泡“已达到输入上限”，约 2.5 秒后消失，继续超限输入会重新提示；剩余字数最低为 0。旧版长文与已存草稿不被自动截断，旧超长草稿需编辑到上限以内再发布。字数规则变更需重新部署整个 userService 后编译小程序。视频后续开发。图片功能的新增部署要求见[动态图片部署与验收](动态图片部署与验收.md)。点赞及评论数量来自数据库，没有预置帖子或模拟热度。转发双箭头与纸飞机均为占位图标，固定显示 0，不绑定功能；客户端拒绝转发请求，云端仅允许点赞互动，历史转发记录不删除。

## 你需要执行的部署操作

**评论区分层回复、点赞与个人折叠的最新部署步骤见 [评论区分层回复部署](评论区分层回复部署.md)。本次新增两个集合、一个复合索引，并需重新部署 `userService`。下文原先“仅前端样式调整无需部署”的说明不适用于这次功能更新。**

沿用当前小程序绑定的云环境和 `userService`，不需要新建云函数。已有集合和索引不用重复创建。删除、举报需要新增 `square_reports` 集合，并重新部署最新云函数；此前配置好的四个索引保留即可。

1. 打开微信开发者工具 → 云开发 → 数据库，确认以下集合存在（只创建缺少的）：

   | 集合 | 用途 |
   | --- | --- |
   | `square_posts` | 广场动态和真实互动数量 |
   | `square_replies` | 动态下的回复 |
   | `square_interactions` | 每个账号的点赞状态（保留历史转发记录） |
   | `square_reports`（本次新增） | 举报人、目标动态、原因、待处理状态及内容快照，仅供管理员处理 |

2. 四个集合均设置为“仅管理员可读写”。特别注意新建的 `square_reports` 不向客户端开放读写。使用自定义安全规则时，分别填写：

   ```json
   { "read": false, "write": false }
   ```

   前端通过云函数浏览公开内容。不能直接开放数据库写入，否则可能绕过板块限制、身份校验和真实计数逻辑。

3. 创建以下普通复合索引（非唯一）：

   | 左侧选择的集合 | 索引名称 | 在同一个索引中按顺序添加的字段 |
   | --- | --- | --- |
   | `square_posts` | `posts_square_feed` | `scope` 升序、`status` 升序、`sortKey` 降序 |
   | `square_posts` | `posts_by_author` | `authorId` 升序、`scope` 升序、`status` 升序、`sortKey` 降序 |
   | `square_replies` | `replies_by_post` | `postId` 升序、`status` 升序、`sortKey` 降序（已有升序索引保留） |
   | `square_interactions` | `interactions_by_user` | `userId` 升序、`active` 升序、`postId` 升序 |

   每行是一个复合索引，索引名与集合名是不同的字段。当前开发环境已经配置过这四个索引，无需重复添加。`square_reports` 本次通过文档 ID 去重，不需要额外索引。

4. 回到编辑器，右键 `cloudfunctions/userService` → **上传并部署：云端安装依赖**。如果菜单显示“创建并部署：云端安装依赖”，选择该项即可。整个文件夹一起部署，包含新增的 `square.js` 和更新后的 `config.json`。

5. `config.json` 已声明 `security.msgSecCheck` 云调用权限。发布动态和回复前会进行文字校验，只有返回通过才落库；校验未通过或服务异常时保留草稿，不提示发布成功。如果提示文字校验服务暂不可用，检查云函数日志、接口权限和当前小程序的内容安全接口可用性。权限声明的官方说明见 [CloudBase 云调用权限说明](https://docs.cloudbase.net/faq/knowledge/cloud-call-604101-permission-error)。

6. 重新编译小程序。首页右下角蓝色加号按钮原位打开底部发布面板；个人主页“发布动态”也使用同一组件。取消后留在来源位置，发布成功后同步真实缓存。

如果此前发布普通文字却提示“该发布入口仅支持动态广场”，需要重新部署最新的整个 `userService` 文件夹，并重新编译前端。旧版把云函数顶层的附带字段也纳入了严格发布参数校验；仅排除 `userInfo` 仍不够稳妥。最新协议将正文、板块和提交标识统一放在独立的 `post` 对象中，只校验该业务对象；身份仍只取可信 `getWXContext()`。已创建的集合、索引不需要重建，原有草稿可以继续发布。前端和云函数必须同时更新。

## 验收顺序

1. 退出登录后打开首页：可以浏览真实动态；长文在卡片内展开，点击评论图标在当前页打开评论面板。发布、点赞或发表评论时才弹出微信登录提示。
2. 使用未认证普通账号登录，点击蓝色发布按钮，输入正文后发布。发布页只显示“动态广场”，没有其他发布目标。
3. 发布成功后回到首页“动态广场”，新动态显示在列表中。退出小程序再进入并刷新，内容仍来自云端。
4. 长文超过 280 字时显示“展开全文”，点击在同一张动态卡片内展开，再点击“收起”。点击卡片正文进入 `pages/square-detail/index`，全文、作者、发布时间和互动栏连续展示，下方直接使用现有评论区，底部固定输入框。预览已缓存的内容同步展示，后台按新鲜度读取；列表的“展开全文”、点赞、评论和菜单操作不额外跳转。
5. 点赞，再次点击取消；同账号重复提交同一个目标状态不会增加多次计数。换另一个普通账号互动，计数应真实增加。
6. 在首页或个人主页点击评论，底部面板显示真实评论，可在面板内填写并发送，成功后同步原卡片的评论数。首次读取评论或更多评论时按需联网，已有缓存先显示；发送失败保留输入与提交标识供重试。
7. 输入正文后点击右上角草稿图标保存，再进入可恢复。有未保存文字或图片时点击取消，显示“保存为草稿 / 不保存 / 继续编辑”弹窗；分别验证保存后退出、清除草稿和本次编辑后退出、保留内容继续编辑。发布失败保留当前编辑内容及重试标识，成功后才清除该账号已存草稿。不同账号的草稿相互独立。
8. 未认证账号切换到“校园圈”时显示认证入口，不会把广场动态显示为校园圈内容。
9. 从首页侧栏进入个人资料，默认“动态”显示当前账号自己的广场动态。点击“动态”旁的下箭头，展开“广场动态 / 校园圈”，选中项为蓝色；点其他位置收起。校园圈保留入口，当前未开发动态列表，不混用广场内容。
10. 个人主页的卡片同样支持进入详情、原地展开和底部评论面板，点赞、评论的真实计数同步到广场和个人主页；下拉刷新，触底读取更早的本人动态。切换账号后不显示上一账号的列表或评论面板。
11. 操作栏按点赞、评论、转发、纸飞机静态展示位排列，四项等宽分布，第一项与正文左侧对齐。点赞、评论的空计数显示 0，转发与纸飞机固定显示 0，点击均不发起请求、不变色。评论与个人主页回复使用同款 SVG。
12. 卡片昵称行右侧为“关注”样式按钮和两条杠，关注暂不可操作，不会伪造已关注状态。点击自己动态的两条杠 → 删除动态 → 确认，成功后首页、个人动态和关联评论缓存同步移除；取消或请求失败时保留。删除由云端重新检查作者身份，不能用客户端作者字段删除他人的动态。删除采用 `status: deleted`，公开列表、单条读取、评论及互动均不可再访问该动态；关联评论不再公开，原记录保留供后续审计。
13. 点击别人动态的两条杠 → 举报动态 → 选择原因 → 提交举报。`square_reports` 中应产生 `pending` 记录，同一账号重复举报同一动态不会重复建档。举报本身不会自动隐藏动态；本轮未增加管理员举报处理页面，管理员可在云控制台查看记录并按需处理。
14. 动态分享功能暂不开发。最右侧纸飞机按参考图绘制为 SVG，仅静态展示并固定显示 0，不绑定点击或分享事件；前端不注册动态分享处理，云端不提供分享计数接口。
15. 首页下拉时，头像和三个标签保持固定，仅标签下方的内容区域下移；蓝色刷新转圈显示在标签与第一条内容之间。刷新成功或失败后收起，旧动态在刷新期间继续显示；滚动触底仍能加载下一页。
16. 卡片“关注”按钮为固定的紧凑宽度。评论面板标题居中，上方横杠可拖动：默认占屏幕约 68%，上拉超过两档间距的一半后吸附至微信胶囊下方 12px；未过一半则复位。展开后向下拖动遵循同样的一半阈值，取消手势回到原档位。拖动不会清空评论或正在输入的文字。
17. 打开评论后底部导航隐藏，关闭评论或离开页面后恢复。默认、展开和键盘弹出时都应显示面板底部的评论输入框与发送键；评论列表在独立区域滚动，不挤出输入区。未登录时该位置显示登录入口，空白文字不能发送，发送失败保留草稿。

## 数据与性能

- 首页、个人动态、完整正文和评论使用本次运行内的账号隔离缓存，一分钟内复用；下拉首页可主动读取最新动态。评论面板发送成功后立即同步卡片计数。
- 个人动态复用同一 `square_posts` 数据源，没有重复保存内容。`listSquarePosts` 的 `mine: true` 从可信微信身份查出本人作者 ID，服务端直接筛选并分页；不从广场首页的一页数据推断本人的完整列表。个人列表独立缓存，发布成功和互动后立即同步，返回页面不清空已有内容。旧云函数未返回本人筛选标识时会提示更新服务，避免误显示其他作者。
- 云端使用可信 OpenID 查到的账号，客户端传入的作者、角色、学校或热度不会作为写入依据。
- 发帖和回复通过提交标识去重；回复与数量、点赞状态与数量在事务中同步写入。超时后重试沿用同一提交标识。
- 删除、举报记录均在事务内验证当前有效账号；删除校验作者，举报禁止举报自己。举报不在公开接口返回。
- 本地记录已删除 ID，清理关联列表、正文和评论缓存；迟到的列表、正文或评论请求不能把已删除动态重新显示出来。

动态分享按钮、计数、链接处理及云端接口已移除。此项调整需要重新编译前端，并重新部署整个 `userService` 以移除云端旧接口；不新增集合或索引。
- 认证徽章按作者当前的有效认证状态生成，不使用发帖时的旧认证快照。退出登录或切换账号后，旧请求不能更新新会话缓存。
- 管理员可通过控制台把某条动态的 `status` 改成 `hidden` 以停止公开展示。后续会补齐面向管理员的内容管理界面。

本地验证：`node --test`。测试不连接真实云环境；真实发布、文字校验及索引是否生效，需要按上述步骤在开发者工具中验收。

## 转发占位调整

重新编译小程序后，所有动态卡片的转发双箭头恢复灰色且固定显示 0，不再提供点击交互。重新部署整个 `cloudfunctions/userService` 后，云端同步拒绝转发写入，并将接口中的转发状态及计数返回为 false / 0；不清除旧记录，不影响点赞和评论。无需新建集合或索引。

## 首页板块切换过渡

首页“动态广场”和“校园圈”使用两个保持挂载的独立滚动面板，点击标签时以 260ms 横向平移切换。顶部使用同一根蓝色指示条，在同次数据更新中提交目标位置及宽度，使用相同时间和缓动平移；文字及箭头范围通过真实布局测量，保留左侧额外延长的 6rpx。往返切换不销毁广场卡片及两个滚动容器，下拉筛选分别保留。关注与校园圈仍使用原有待开放或认证提示，不新增业务权限或模拟内容。本次只需重新编译前端。

## 点赞即时反馈

点击点赞或取消后立即更新目标卡片的爱心和数量，后台再通过现有目标状态接口保存。同一动态同时只保存一笔请求，期间的连续点击合并为最新选择；其他动态可独立保存。保存失败恢复最近一次已确认状态并提示，相关缓存过期以便后续重新核对。首页与个人主页通过共享缓存通知同步，刷新期间也保留待保存的选择；迟到响应不得恢复已删除动态或进入新账号缓存。点赞成功不弹成功提示，不重写整张列表，也不覆盖评论数量。

验证包含延迟返回下的即时显示、连续取消、请求合并、失败回退、缓存刷新、并行评论、删除及账号切换。本轮只需重新编译前端，无需更新云函数。

- 右上两条杠打开“添加内容声明”，不显示顶部横杠及预览说明。内容包括无需声明、AI 生成、个人观点和见解、转载信息、虚构演绎、营销信息，选择随真实发布和明确保存的草稿保存。底部“动态设置”展示“谁能回复和引用”“谁能查看”两组独立单选，选项均为任何人、我的萃友、我的粉丝、我的关注。动态设置不显示顶部横杠、审核回复开关及预览说明，与声明面板一样按内容自然撑高，不使用内部滚动；短屏适度缩紧选项行，完成按钮紧接内容，保留底部安全区。选中声明后，工具栏上方显示可点击的浅灰胶囊“已包含内容声明”及右箭头，点击可修改选择，改为无需声明后隐藏。
- **回复范围、查看范围仍仅为本地界面选择，不改变实际权限，也不存入数据库或随发布请求发送。贴纸和 GIF 暂不接入功能。** 内容声明已接通真实保存与展示。图片图标现已接通相册/拍照，最多 9 张，需按[动态图片部署与验收](动态图片部署与验收.md)更新云端。文字发布、长度限制、失败重试去重与成功后清除草稿继续使用原有真实流程。
- 关闭面板保留首页或个人主页原列表位置，不先跳回首页再进入其他页面；发布成功后同步来源列表缓存。面板样式本身只改前端，当前新增的图片发布功能还需更新云端，具体见[动态图片部署与验收](动态图片部署与验收.md)。
- 验收 iOS/Android 键盘弹起与收起、切换后台回来保持草稿、帖子选项和内容声明的选择、保存失败不丢字、取消原位恢复、成功发布同步列表、快速重复点击与切换账号不串用草稿。

### 取消发布与未保存提示

- 当前有文字或图片未保存时，点击取消或发布面板外部，收起键盘并显示居中的圆角三选项弹窗，背景遮罩阻止操作下方发布页。蓝色“保存为草稿”复用真实图文草稿保存流程，成功才退出；红色“不保存”删除当前账号草稿并丢弃本次编辑后退出；“继续编辑”关闭弹窗，保留内容并恢复输入。点击遮罩不触发退出。
- 清空内容后取消会同时删除当前账号的本地草稿，再次打开保持空白；未修改的已存草稿可直接退出并保留。组件卸载和后台事件不会自动保存内容，右上角保存仍会提示成功并收起发布面板。
- 清空本次编辑后取消退出，会删除当前账号的已存草稿，防止旧内容再次恢复；不会删除其他账号的草稿。只有明确点击保存才写入新版本。弹窗中的保存或清除失败时保留内容并显示错误，可重试或继续编辑；保存图片期间禁止重复保存或丢弃，切换账号后的迟到响应不能关闭新账号面板。
- 发布失败继续保留当前面板中的正文和幂等标识，可直接重试；同账号重新登录不以旧草稿覆盖当前编辑内容。

### 内容声明部署与验收

- 先在微信开发者工具中对整个 `cloudfunctions/userService` 执行“上传并部署：云端安装依赖”，成功后重新编译小程序。无需新增集合、索引或修改存储规则。旧云函数尚不接受新声明字段，不要仅编译前端就测试带声明发布。
- 声明使用 `square_posts.declaration` 独立字段，服务端只接受 `none / ai / opinion / repost / fiction / marketing`；不拼接正文，不占用正文 150 字额度。未传字段及旧动态默认 `none`。相同请求重试不得更换声明，修改选择后客户端生成新的提交标识。
- 首页、本人动态和详情使用相同展示：纯文字在正文末尾单独一行，带图在图片下方，左侧与正文/图片对齐，并显示感叹号图标。无需声明和旧动态不显示标记，相册仍只显示图片。
- 逐一验证五种声明、无需声明、纯图片、长文展开、保存草稿后重新打开；只修改声明也应触发未保存退出确认。失败重试保留选择，切换账号不能继承其他账号的声明。
