# 动态广场部署与验收

## 本轮范围与最新参与规则

- 游客可以浏览公开广场动态与评论，发布和互动需要微信登录。当前不设置独立动态详情页。
- 普通登录用户无需学校认证，即可发布文字动态、点赞、转发和回复。广场发布入口固定为 `square`，没有校园圈或其他板块选项。
- 校园圈、跑腿和集市的加入与业务参与保留学校认证限制；这些业务、关注流、私信和好友功能后续开发。本轮不修改或假装实现它们。
- 当前支持 1—1000 字的文字动态、1—300 字的文字回复；图片和视频后续开发。互动数量全部来自数据库，没有预置帖子或模拟热度。转发本轮表示转发记录及计数，个人主页的转发列表后续接入。

## 你需要执行的部署操作

**评论区分层回复、点赞与个人折叠的最新部署步骤见 [评论区分层回复部署](评论区分层回复部署.md)。本次新增两个集合、一个复合索引，并需重新部署 `userService`。下文原先“仅前端样式调整无需部署”的说明不适用于这次功能更新。**

沿用当前小程序绑定的云环境和 `userService`，不需要新建云函数。已有集合和索引不用重复创建。本次删除、举报与分享计数需要新增 `square_reports` 集合，并重新部署最新云函数；此前配置好的四个索引保留即可。

1. 打开微信开发者工具 → 云开发 → 数据库，确认以下集合存在（只创建缺少的）：

   | 集合 | 用途 |
   | --- | --- |
   | `square_posts` | 广场动态和真实互动数量 |
   | `square_replies` | 动态下的回复 |
   | `square_interactions` | 每个账号的点赞、转发状态，以及分享发起事件的去重记录 |
   | `square_reports`（本次新增） | 举报人、目标动态、原因、待处理状态及内容快照，仅供管理员处理 |

2. 四个集合均设置为“仅管理员可读写”。特别注意新建的 `square_reports` 不向客户端开放读写。使用自定义安全规则时，分别填写：

   ```json
   { "read": false, "write": false }
   ```

   前端通过云函数浏览公开内容。不能直接开放数据库写入，否则可能绕过板块限制、身份校验和真实计数逻辑。

3. 创建以下普通复合索引（非唯一）：

   | 左侧选择的集合 | 索引名称 | 在同一个索引中按顺序添加的字段 |
   | --- | --- | --- |
   | `square_posts` | `posts_square_feed` | `scope` 升序、`status` 升序、`sortKey` 降序 |
   | `square_posts` | `posts_by_author` | `authorId` 升序、`scope` 升序、`status` 升序、`sortKey` 降序 |
   | `square_replies` | `replies_by_post` | `postId` 升序、`status` 升序、`sortKey` 升序 |
   | `square_interactions` | `interactions_by_user` | `userId` 升序、`active` 升序、`postId` 升序 |

   每行是一个复合索引，索引名与集合名是不同的字段。当前开发环境已经配置过这四个索引，无需重复添加。`square_reports` 本次通过文档 ID 去重，不需要额外索引。

4. 回到编辑器，右键 `cloudfunctions/userService` → **上传并部署：云端安装依赖**。如果菜单显示“创建并部署：云端安装依赖”，选择该项即可。整个文件夹一起部署，包含新增的 `square.js` 和更新后的 `config.json`。

5. `config.json` 已声明 `security.msgSecCheck` 云调用权限。发布动态和回复前会进行文字校验，只有返回通过才落库；校验未通过或服务异常时保留草稿，不提示发布成功。如果提示文字校验服务暂不可用，检查云函数日志、接口权限和当前小程序的内容安全接口可用性。权限声明的官方说明见 [CloudBase 云调用权限说明](https://docs.cloudbase.net/faq/knowledge/cloud-call-604101-permission-error)。

6. 重新编译小程序。首页右下角蓝色羽毛按钮进入广场发布页；认证用户个人主页已有的“发布动态”入口也已连接该页面。

如果此前发布普通文字却提示“该发布入口仅支持动态广场”，需要重新部署最新的整个 `userService` 文件夹，并重新编译前端。旧版把云函数顶层的附带字段也纳入了严格发布参数校验；仅排除 `userInfo` 仍不够稳妥。最新协议将正文、板块和提交标识统一放在独立的 `post` 对象中，只校验该业务对象；身份仍只取可信 `getWXContext()`。已创建的集合、索引不需要重建，原有草稿可以继续发布。前端和云函数必须同时更新。

## 验收顺序

1. 退出登录后打开首页：可以浏览真实动态；长文在卡片内展开，点击评论图标在当前页打开评论面板。发布、点赞或发表评论时才弹出微信登录提示。
2. 使用未认证普通账号登录，点击蓝色发布按钮，输入正文后发布。发布页只显示“动态广场”，没有其他发布目标。
3. 发布成功后回到首页“动态广场”，新动态显示在列表中。退出小程序再进入并刷新，内容仍来自云端。
4. 长文超过 280 字时显示“展开全文”，点击在同一张动态卡片内展开，再点击“收起”。头像、昵称和正文不再跳转页面，`pages/square-detail/index` 已从路由及页面文件中移除。预览已缓存全文，展开无需等待新请求。
5. 点赞或转发，再次点击取消；同账号重复提交同一个目标状态不会增加多次计数。换另一个普通账号互动，计数应真实增加。
6. 在首页或个人主页点击评论，底部面板显示真实评论，可在面板内填写并发送，成功后同步原卡片的评论数。首次读取评论或更多评论时按需联网，已有缓存先显示；发送失败保留输入与提交标识供重试。
7. 输入草稿后关闭发布页，再进入，草稿恢复。发布失败后重试不会重复创建帖子；成功后才清空草稿。不同账号的草稿相互独立。
8. 未认证账号切换到“校园圈”时显示认证入口，不会把广场动态显示为校园圈内容。
9. 从首页侧栏进入个人资料，默认“动态”显示当前账号自己的广场动态。点击“动态”旁的下箭头，展开“广场动态 / 校园圈”，选中项为蓝色；点其他位置收起。校园圈保留入口，当前未开发动态列表，不混用广场内容。
10. 个人主页的卡片同样支持原地展开和底部评论面板，点赞、转发、评论的真实计数同步到广场和个人主页；下拉刷新，触底读取更早的本人动态。切换账号后不显示上一账号的列表或评论面板。
11. 四个操作按点赞、评论、转发、分享排列，等宽居中，空计数显示 0。分享图标为纸飞机，评论与个人主页回复使用同款 SVG。
12. 卡片昵称行右侧为“关注”样式按钮和两条杠，关注暂不可操作，不会伪造已关注状态。点击自己动态的两条杠 → 删除动态 → 确认，成功后首页、个人动态和关联评论缓存同步移除；取消或请求失败时保留。删除由云端重新检查作者身份，不能用客户端作者字段删除他人的动态。删除采用 `status: deleted`，公开列表、单条读取、评论、互动及分享均不可再访问该动态；关联评论不再公开，原记录保留供后续审计。
13. 点击别人动态的两条杠 → 举报动态 → 选择原因 → 提交举报。`square_reports` 中应产生 `pending` 记录，同一账号重复举报同一动态不会重复建档。举报本身不会自动隐藏动态；本轮未增加管理员举报处理页面，管理员可在云控制台查看记录并按需处理。
14. 点击纸飞机触发微信原生分享，`shareCount` 在云端记录并同步卡片。分享路径为首页，带目标动态 ID；接收者打开后在首页卡片中看到对应动态，不进入详情页。此数字的口径是登录用户发起分享的次数，取消分享面板仍属于已发起；不代表分享送达次数，不显示“分享成功”提示。参考 [微信官方分享事件与返回值定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.page.d.ts)。每次发起带独立提交标识，相同请求重试不重复增加。未登录点击先请求登录，计数失败不虚增本地数字。
15. 首页下拉时，头像和三个标签保持固定，仅标签下方的内容区域下移；蓝色刷新转圈显示在标签与第一条内容之间。刷新成功或失败后收起，旧动态在刷新期间继续显示；滚动触底仍能加载下一页。
16. 卡片“关注”按钮为固定的紧凑宽度。评论面板标题居中，上方横杠可拖动：默认占屏幕约 68%，上拉超过两档间距的一半后吸附至微信胶囊下方 12px；未过一半则复位。展开后向下拖动遵循同样的一半阈值，取消手势回到原档位。拖动不会清空评论或正在输入的文字。
17. 打开评论后底部导航隐藏，关闭评论或离开页面后恢复。默认、展开和键盘弹出时都应显示面板底部的评论输入框与发送键；评论列表在独立区域滚动，不挤出输入区。未登录时该位置显示登录入口，空白文字不能发送，发送失败保留草稿。

## 数据与性能

- 首页、个人动态、完整正文和评论使用本次运行内的账号隔离缓存，一分钟内复用；下拉首页可主动读取最新动态。评论面板发送成功后立即同步卡片计数。
- 个人动态复用同一 `square_posts` 数据源，没有重复保存内容。`listSquarePosts` 的 `mine: true` 从可信微信身份查出本人作者 ID，服务端直接筛选并分页；不从广场首页的一页数据推断本人的完整列表。个人列表独立缓存，发布成功和互动后立即同步，返回页面不清空已有内容。旧云函数未返回本人筛选标识时会提示更新服务，避免误显示其他作者。
- 云端使用可信 OpenID 查到的账号，客户端传入的作者、角色、学校或热度不会作为写入依据。
- 发帖和回复通过提交标识去重；回复与数量、点赞/转发状态与数量在事务中同步写入。超时后重试沿用同一提交标识。
- 删除、举报、分享记录均在事务内验证当前有效账号；删除校验作者，举报禁止举报自己，分享记录和计数同时写入。举报不在公开接口返回。旧动态没有 `shareCount` 时按 0 展示，无需迁移。
- 本地记录已删除 ID，清理关联列表、正文和评论缓存；迟到的列表、正文或评论请求不能把已删除动态重新显示出来。

本次“关注＋两条杠、移除详情页、底部评论面板”是前端调整，重新编译即可；不需要为这次调整新增集合、索引或部署云函数。此前删除、举报与分享接口所需的云端部署仍沿用上面的说明。
- 认证徽章按作者当前的有效认证状态生成，不使用发帖时的旧认证快照。退出登录或切换账号后，旧请求不能更新新会话缓存。
- 管理员可通过控制台把某条动态的 `status` 改成 `hidden` 以停止公开展示。后续会补齐面向管理员的内容管理界面。

本地验证：`node --test`。测试不连接真实云环境；真实发布、文字校验及索引是否生效，需要按上述步骤在开发者工具中验收。
