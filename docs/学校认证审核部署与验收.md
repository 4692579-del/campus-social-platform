## 使用流程

1. 普通账号在“我的 → 申请学校认证”提交资料，进入待审核状态。
2. 管理员账号登录同一个小程序，进入“我的 → 管理工作台 → 学校认证审核”。列表可切换待审核、已通过、已驳回；每次读取 20 条，可继续加载。
3. 进入详情，查看学校、姓名、学号和提交时间。点击“查看认证材料”，材料成功显示后可点击放大。
4. 通过时确认学校全称；页面要求先看到材料并弹出确认窗口。驳回时填写 2—200 个字的具体原因，也需要确认。
5. 用户返回“我的”，页面会重新向云端读取身份。通过后显示学生用户、认证学校；驳回后可查看原因、重新选择材料并提交。

列表展示各账号的最新一份申请。用户驳回重提后，最新申请移到待审核分类；上一轮审核结果仍保存在独立审核记录集合，当前没有提供历史版本查询页面。

## 部署准备

保持当前环境 `campus-social-dev-d3dmcsfefdcae4`，先完成以下配置，再部署云函数：

1. 新建数据库集合 `certification_reviews`，权限设为“所有用户不可读写”（云控制台和云函数服务端仍可访问）。该集合记录审核人、申请版本、决策、学校、原因和时间。
2. 已有 `users`、`certification_applications` 继续限制客户端直接读写。不要为了显示审核列表而开放集合权限；列表通过鉴权云函数读取。
3. 在 `certification_applications` 的“索引管理”创建非唯一组合索引 `review_status_submitted_id`，字段依次如下：

| 顺序 | 字段 | 排序 |
| --- | --- | --- |
| 1 | status | 升序 |
| 2 | submittedAt | 降序 |
| 3 | _id | 降序 |

等索引创建成功后再验收列表。查询按状态筛选，再按提交时间和主键降序读取。索引配置依据：[CloudBase 索引管理](https://docs.cloudbase.net/database/data-index)。

4. 保留上一步的私有存储规则，`certification-proofs/` 不向客户端开放。保留 `userService` 环境变量 `CERTIFICATION_UPLOAD_ENABLED=true` 和 20 秒超时。
5. 在开发者工具右键 `cloudfunctions/userService`，选择“创建并部署：云端安装依赖”。包括新文件 `certification-review.js`，不只上传入口文件。保存后检查云函数配置中上传开关仍为 true；不要通过前端硬编码管理员绕过权限。
6. 编译后测试。手机需重新预览或更新体验版本，管理员微信号仍使用前面已初始化的独立账号。

如果出现“不支持此操作”，说明云函数还是旧版本；如果列表读取失败，检查索引及云函数部署。若审核保存失败且用户仍待审核，先检查新集合 `certification_reviews` 是否已创建，事务不会只更新一半。

## 权限与数据一致性

- 四个接口 `listCertifications`、`getCertificationDetail`、`getCertificationProof`、`reviewCertification` 都重新按微信 OpenID 查当前云端角色。普通用户和学生无法访问，客户端的 role、openid 或 userId 无法授权。
- 材料只允许当前环境 `certification-proofs/申请人账号ID/` 下、符合系统随机文件名格式的图片。管理员主动查看时生成 120 秒临时链接；不会返回到普通用户查询、审核列表或公开个人资料里。[微信云函数 SDK 接口定义](https://github.com/wechat-miniprogram/wx-server-sdk/blob/master/index.d.ts)提供了服务端临时链接与文件读取能力。
- 临时链接在失效前可用于读取该图片；撤销管理员权限会阻止后续接口请求，但已经签发的链接会在有效期结束后失效。页面隐藏后清空材料链接和私人详情，不写本地缓存。
- 审核通过前，云函数确认图片可从私有存储读取。材料缺失时不能通过，可以说明原因驳回。
- 每次审核携带当时读取到的申请版本。已被审核的申请不能再审核；用户重新提交后，旧版本页面不能操作新材料。
- 申请结果、用户角色与学校、独立审核记录和审核员时间在同一个事务中保存。任何一步失败全部回滚。事务内再次读取审核员与申请人状态，防止管理员被撤权、申请人被封禁或角色变化时继续更新。
- 管理员不能审核自己；审核接口不能修改管理员角色。通过只将有效申请人升级为 student，驳回保持 user。认证状态与学校一起更新，认证材料及姓名学号不会进入公开个人资料。

## 学校归属

当前还没有独立的学校目录。管理员核对材料后填写统一的学校全称；服务端先规范全角/半角字符，再按全称去掉空白后的内容生成稳定 schoolId，同一核准名称产生同一归属。客户端不能自行指定 schoolId。

请避免同一学校混用简称、别名；不同文字名称不会自动判断成同一所学校。申请中填写的 schoolName 保留原文，核准名称写入 approvedSchoolName，并同步为 users.schoolName。后续引入学校目录时，需要统一映射已有学校标识，而不是直接批量重置用户。

## 验收用例

| 操作 | 预期结果 |
| --- | --- |
| 管理员进入审核列表 | 显示待审核申请，空列表有说明，无虚假数量 |
| 普通账号直接打开审核页或调用四个审核接口 | 云端拒绝，不显示申请详情或材料 |
| 查看材料 | 图片可显示和放大；公开头像继续正常显示 |
| 材料加载失败 | 通过按钮不可用；可重新查看或说明原因驳回 |
| 通过申请 | 列表移到已通过；用户为 student、approved，schoolId 非空，认证学校显示正确 |
| 驳回且不填原因 | 不发送审核请求 |
| 驳回后用户进入认证页 | 可看到原因；重新选择材料提交后 revision 递增，role 仍为 user |
| 旧详情页面审核用户新提交的版本 | 提示刷新，必须重新核对新材料 |
| 重复点击或两位管理员同时处理 | 仅一个决策生效，不重复创建同版本审核记录 |
| 审核请求超时 | 页面查询最新结果，不自动再次执行；状态未确认时暂停审核 |
| 审核时管理员被撤权/封禁或申请人变成管理员/被封禁 | 拒绝更新，原角色和申请结果不被覆盖 |
| 任一事务写入失败 | 申请仍待审核，用户未升级，不出现半条审核结果 |
| 返回列表或切换账号 | 重新加载并鉴权，旧页面数据与图片链接已清空 |

分页使用提交时间排序与偏移量，其他管理员处理申请可能改变列表位置；从详情返回会自动重新读取第一页。多管理员同时操作时也可以下拉刷新，服务端仍会检查版本和待审核状态。
