# 评论区分层回复：部署与验收

这次增加了真实回复关系、评论点赞和每个账号单独保存的心碎折叠状态，需要更新云端。此前仅调整评论面板样式时无需部署的说明，不适用于这次功能更新。

## 配置顺序

1. 打开微信开发者工具 → 云开发 → 数据库，在当前 `campus-social-dev` 环境中创建两个集合（已有就不用重复创建）：

   | 集合名称 | 用途 |
   | --- | --- |
   | `square_reply_children` | 一级评论下的回复，以及回复对象之间的关系 |
   | `square_comment_states` | 每个账号对每条评论的点赞、心碎折叠状态 |

2. 两个集合的权限均设为“仅管理员可读写”。自定义规则为 `{"read": false, "write": false}`；客户端通过 `userService` 访问。

3. 只在 **`square_reply_children`** 新增下面这一个普通复合索引，选“非唯一”：

   - 索引名称：`children_by_root`
   - 在同一个索引内，按顺序添加：`postId` 升序、`rootId` 升序、`status` 升序、`sortKey` 升序。

   等待索引创建完成。`square_comment_states` 按确定的文档主键查询，不需要新增复合索引。之前四个广场索引继续保留。

4. 回到代码编辑器，右键整个 `cloudfunctions/userService` 文件夹 → **上传并部署：云端安装依赖**。需要包含最新的 `square.js` 和 `service.js`，不要只上传单个文件。

5. 重新编译小程序，关闭评论区再打开，或点击“重试”。原有 `square_replies` 评论保留为一级评论，原有数据不需要迁移或删除。

## 截图中的“服务暂时不可用”

这是云函数失败时旧版统一返回的提示，缓存中的评论仍会保留在画面中。新版会查询 `square_comment_states`；如果集合未创建，云端读取就会失败。CloudBase 对应的错误类别是 [`DATABASE_COLLECTION_NOT_EXIST`](https://docs.cloudbase.net/error-code/basic/DATABASE_COLLECTION_NOT_EXIST)。

代码已将评论相关的缺失集合错误单独返回为 `COMMENTS_STORAGE_NOT_READY`，界面提示“评论服务尚未配置完成，请稍后再试”。这项错误分类也需要部署最新云函数才能生效。它不代表其他未知数据库或网络错误已解决。

如果上述配置完成后仍报错，在云开发 → 云函数 → `userService` → 日志中查看最新一次失败调用：缺失集合时日志会记录 `userService comments configuration: missing collection`。本地测试不连接云环境，不能替代这一步确认。

## 验收规则

- 时间显示在评论正文下方。点击评论可指定回复对象，底部显示“回复 昵称”，可取消并改为评论动态。
- 已有回复默认折叠，点击“展开 N 条回复”才读取并显示；较多回复按页读取。
- 原本零回复的评论：新回复直接显示，并出现“收起”；收起后再点击展开可恢复。
- 原本已有回复的评论：旧回复维持折叠，本次新回复单独显示在展开按钮下方；不重复插入到已展开列表。
- 关闭评论区再打开，本次临时显示规则结束，所有已有回复恢复默认折叠。
- 爱心记录真实点赞，可以取消，重复提交和并发请求不会虚增数量。
- 心碎只保存当前账号的折叠状态。一级评论折叠后用感叹号与“该评论已折叠”替代正文，并隐藏整组回复；再次点击恢复。折叠子回复时，其后续回复也隐藏，其他同级回复保留。切换账号后互不影响。
- 未登录可以阅读；回复、点赞与心碎操作需要登录。普通未认证账号可参与。
- 发送失败保留文字和回复对象，重试不会重复写入。切换账号或离开页面，迟到响应不得恢复旧账号数据。

本地检查：`node --test`。本次未代为部署云函数或创建云端集合。
