# 学校认证取消与撤回：部署与验收

本次复用现有 `userService`、`users`、`certification_applications` 和审核页面，不引入新依赖、集合或索引。

## 用户操作

- 待审核：进入“我的 → 查看认证申请”，点击“取消认证”，二次确认后撤回申请。
- 已通过：进入同一认证页面，点击“撤回认证”；确认后恢复未认证普通用户，并清空认证学校。
- 成功后认证页立即开放申请表。重新申请需重新填写资料、选择材料和确认用途；昵称、头像、账号 ID 不变。
- 未申请、已驳回、管理员账号不显示撤回按钮。驳回后直接修改并重提即可。

## 部署

1. 在微信开发者工具右键 `cloudfunctions/userService`，选择“创建并部署：云端安装依赖”。
2. 保留现有私有数据库和存储规则，以及 `CERTIFICATION_UPLOAD_ENABLED=true` 配置。
3. 云函数部署后重新编译。真实管理员或学生在手机测试时，也需使用更新后的预览代码包/体验版本。

必须更新云函数后再测试新按钮。旧版本云函数不识别 `withdrawCertification`，旧版本客户端查询的申请信息也没有供撤回使用的 `revision`。

## 状态及并发处理

- 客户端提交当前申请编号、版本与原状态；服务端只操作可信微信身份对应的本人申请，并在事务中重新检查账号状态。
- 待审核取消：`pending → withdrawn`；已通过撤回：`approved → withdrawn`。同时将用户设置为 `role=user`、`certificationStatus=unverified`，清空 `schoolId`、`schoolName`。写入失败时全部回滚。
- `withdrawn` 是私有数据库中的内部状态，不向本人申请页或管理员列表、详情、材料接口返回。再次申请时覆盖最新槽位并递增版本，不物理删除账号或申请文档。
- 内部申请记录和既有审核历史保留，材料继续受私有存储保护；撤回不等同于删除历史材料。已经签发的材料临时链接仍可能在剩余有效期内读取，最长为原来的 120 秒；撤回后不能再次获取材料链接。
- 管理员刷新列表或重新进入列表后，撤回申请消失。已打开的页面不会实时收到推送；再次读取材料、刷新详情或审核时，服务端拒绝并清除页面旧详情。
- 管理员先通过时，原“取消待审核申请”请求会提示状态变化，不会自动撤销刚获得的学生身份。用户需看见已通过状态后，再明确确认“撤回认证”。
- 用户先取消时，管理员旧页面不能通过或驳回该申请。重新提交后，旧审核/旧撤回请求也不能操作新版本。
- 同一版本重复撤回可安全确认原结果；已经撤回的提交标识被保留为私有校验信息，多轮操作后迟到的旧提交重试也不能重新发布申请。
- 请求超时只查询最新状态，不自动重复撤回；若查询也失败，页面暂停撤回，要求先刷新确认状态。

后续加入动态、交易和跑腿模块时，各服务应继续按当前云端认证与学校归属鉴权；本次尚未添加这些业务。

## 验收

| 用例 | 预期结果 |
| --- | --- |
| A 提交申请，管理员打开待审核列表 | 管理员能看到 A 的申请 |
| A 点击取消认证，在确认框选取消 | 申请保持待审核 |
| A 确认取消认证 | 立即显示未认证，重新开放申请表 |
| 管理员刷新列表 | A 的申请不再出现 |
| 管理员从旧详情尝试查看材料或审核 | 提示已撤回/不存在，详情清空，不更新用户身份 |
| A 再次申请 | 同一账号新版本申请进入待审核，可正常审核 |
| 管理员通过后 A 撤回认证 | A 恢复普通用户，认证学校清空，昵称头像保留 |
| A 退出重新登录或重新编译 | 仍为未认证，未恢复旧学校或学生身份 |
| 已通过撤回后再次申请并通过 | 学校和学生身份正常恢复 |
| 旧取消请求与管理员通过同时执行 | 状态一致，不会误撤回已经通过的认证 |
| 未登录、其他用户、封禁账号、管理员调用撤回接口 | 服务端拒绝，原用户和申请不被覆盖 |
