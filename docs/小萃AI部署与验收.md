# 小萃小萃 AI 评论

## 发布和回复的共用文字检查

### 腾讯云文本审核（当前接入方式）

发布动态、评论、楼中回复、小萃回答及润色原文/结果均由 `content-check.js` 选择检查服务。用户已开通腾讯云标准文本内容安全，创建并验证策略 `campus_social_text`；云端还需要部署本次代码才会切换。

1. 云函数 `userService` 的环境变量保留已有项目，新增：

   | Key | Value |
   | --- | --- |
   | `TEXT_CHECK_PROVIDER` | `tencent_tms` |
   | `TMS_SECRET_ID` | 自行保存的CAM子用户SecretId |
   | `TMS_SECRET_KEY` | 对应SecretKey |
   | `TMS_BIZ_TYPE` | `campus_social_text` |

   这四项已由用户在云端配置，无需把值交给开发工具或写入源码。默认地域 `ap-guangzhou`，如需其他支持地域可设 `TMS_REGION`。子用户只需自定义策略 `CampusTextModerationOnly`：允许 `tms:TextModeration`，资源 `*`；不需要管理员权限。
2. 执行超时改为 **60秒**并保存。微信开发者工具右键整个 `cloudfunctions/userService` → **上传并部署：云端安装依赖**。必须包含新的 `content-check.js`、`tencent-content-check.js`、更新的 `index.js`、`wechat-content-check.js` 及目录中其余文件。本接入使用Node内置HTTPS/crypto，无新增npm依赖。
3. 部署后重新编译，分别测试发布短动态、普通评论、“问问小萃”及正文优化。到腾讯云内容安全控制台的文本审核明细查看新记录；之前控制台“在线审核”通过只证明策略可用，不能证明云函数已接入。本地模拟测试未使用真实凭证，不能代替部署后的真实验收。
4. 请求固定发送到 `https://tms.tencentcloudapi.com/`，版本 `2020-12-29`，Action `TextModeration`，Type `TEXT`（内容安全，非AI生成识别）。原文按UTF8/Base64编码；不附带openid或账号资料。仅 `Suggestion: Pass` 继续提交；`Review/Block` 拒绝。未知结果、超时、鉴权、余额及额度故障均停止提交，不跳过检查、不自动重试或回退微信。`TEXT_CHECK_PROVIDER` 拼错或缺少TMS配置也不静默回退。
5. 发帖、评论和优化故障提示会标明腾讯云及安全错误码；服务日志 `userService text check: tencent_tms check code: ...` 仅输出经过筛选的错误码，不打印上游错误原文、正文、凭证或签名。`AuthFailure/UnauthorizedOperation` 核对CAM凭证与权限；`ResourceUnavailable` 核对服务和余额；`LimitExceeded/RequestLimitExceeded` 核对腾讯云额度和频率。小萃回复失败仍保留已成功提交的用户评论。

腾讯云与微信是独立审核服务，选择腾讯云后这些文字操作不再调用微信msgSecCheck。腾讯云调用仍按其服务计费：首次开通的3000条体验额度有效期15天，用完或到期后按已开通服务的计费规则扣费，润色成功通常会检查两次。密钥只在云端环境变量保存。若显式改回 `TEXT_CHECK_PROVIDER=wechat` 或移除provider配置，将恢复下面的微信检查方式及对应限制。

参考：[腾讯云文本审核接口](https://cloud.tencent.com/document/api/1124/51860)、[地域与公共参数](https://cloud.tencent.com/document/api/1124/51864)、[TC3签名](https://cloud.tencent.com/document/api/213/30654)、[快速入门](https://cloud.tencent.com/document/product/1124/37119)、[计费说明](https://cloud.tencent.com/document/product/1124/37118)。

### 微信检查（兼容方式及此前45009排查）

**本次45009排查结论：** 微信 `msgSecCheck` 官方文档“注意事项”规定，未上架小程序最多100次/天；通常的200万次/天不适用于此阶段。用户已确认从未正式发布，查询已用126次，随后云调用及HTTPS均在内容检查阶段返回45009，与该特殊限制吻合。不能因getApiQuota返回通用200万额度就排除未上架限制；该查询接口文档也要求特殊quota以具体接口说明为准。切换云调用/HTTPS或重复部署不能解除它。开发期应等待下个日额度周期恢复并控制测试频次；正式审核发布须按正常发布流程安排，不能为排错擅自上线。每次成功润色通常包含原文和结果两次检查，发帖、评论和AI回复也会消耗同一小程序额度。代码不会跳过检查发布，也不承诺后台“清空调用量”能重置这项特殊额度。[微信官方文本检查文档](https://developers.weixin.qq.com/miniprogram/dev/server/API/sec-center/sec-check/api_msgseccheck.md)

仅在provider为 `wechat` 或未设置时使用 `wechat-content-check.js`。当云调用报45009，但HTTPS查得 `/wxa/msg_sec_check` 日额度仍有余额时，不能直接认定该接口日额度耗尽，也不能跳过审核发布。可配置同一微信文本检查接口的HTTPS调用方式，以验证并排除云调用路径上的问题：

1. 云开发 → 云函数 → `userService` → 版本与配置 → `$LATEST` → 配置 → 环境变量，新增 `WECHAT_APP_SECRET`，值为当前小程序的AppSecret。保留原有DeepSeek和认证变量；密钥只在云端填写，不提交Git或发到聊天。小程序AppID自动来自可信的 `cloud.getWXContext().APPID`，不使用客户端传入值。当前项目配置AppID为 `wx59fca34f41bcd10b`，请确认AppSecret属于这个小程序。
2. 保存后右键整个 `cloudfunctions/userService` → 上传并部署：云端安装依赖，必须包含新增 `wechat-content-check.js`；执行超时继续设为60秒。重新编译后各测试一次发帖、回复和优化。
3. 配置后使用官方HTTPS `stable_token`（`force_refresh: false`）和 `/wxa/msg_sec_check`，沿用版本2、场景3和服务端认证的openid；稳定凭证在有效期内缓存，同实例并发获取合并，不强制刷新。不配置变量时继续使用原有云调用。
4. 通过才继续业务提交；`review / risky / block` 和87014均拒绝。网络失败、45009及配置问题不自动重试，不切换路径放行、不伪造成功。发布和回复会显示具体安全错误码。日志 `userService text check:` 只包含 `https/cloud`、`token/check` 和错误码，区分凭证接口受限与内容接口受限，不记录密钥、token、正文或openid。
5. 若显示40164，需核对微信后台的服务端IP白名单与云函数实际出口IP；不能盲目填本电脑IP或删除已有白名单。若直连仍报45009，应依据日志中的 `token/check` 阶段核对对应接口额度；本地模拟测试不能证明云端限流原因或实际恢复情况。

## 关于小萃AI与每日使用额度

- 侧栏账号区域的顶部留白减少84rpx（当前头像高度），带动账号资料和菜单整体上移；工具区在“设置”上方新增“关于小萃AI”，使用黑色小萃SVG。首页进入新页面时保留展开菜单，返回同步恢复首页。页面路径 `pages/xiaocui-about/index`，注册在 `app.json`。
- 页面使用小萃形象、轻量说明和独立用量卡片，展示真实“今日用量／已使用百分比”和进度条，只写“每日0点重置额度”，不展示字数换算规则。可手动刷新及下拉刷新，读取失败不伪造0%；已有同账号同周期缓存同步展示，后台读取保留当前内容，退出、换账号、隐藏和跨日的迟到响应不覆盖当前页面。布局信息层次参考[Claude官方用量页面说明](https://support.claude.com/en/articles/9797557-usage-limit-best-practices)。
- 服务端规则（不放入产品页面）：每个真实账号每天15000个Unicode码点，评论AI回答和正文润色共用；累计每150字消耗1%，空格、换行、emoji及标点均计数，短输出按实际字数累加。只结算通过检查并成功保存/返回的最终输出，失败、未通过检查和评论保存回滚不计入用量；同一已完成评论任务重复查询不重复扣额。已有20次/天和10秒限制不恢复，旧quota/polish_quota记录继续忽略。
- `ai-usage.js` 使用可信服务端时间按北京时间自然日分桶，0点无需定时任务即可使用新周期。复用管理员专属 `square_ai_jobs`，新记录类型 `daily_usage`，仅含账号、日期、累计字数与随机预留令牌，不保存润色正文。`getAIUsage` 只查当前登录账号，客户端账号、百分比或日期不能控制实际额度；返回值不含字数换算参数和其他账号信息。
- 调用模型前通过事务预留最多150字，防止并发超用，完成后按实际输出结算；不足150字的余额作为该次最终输出的上限。异常请求释放预留，云函数中断的预留120秒后失效。AI回复落库和扣额共用事务，保存失败两者一同回滚。跨午夜在途请求结算到发起日期，不污染新一天；耗尽时停止调用模型，普通评论仍正常提交，额度不足不会消耗模型重试次数。
- 部署：上传整个 `cloudfunctions/userService`（含 `ai-usage.js`、更新的 `service.js`、`ai-errors.js`、`square-ai.js`、`square-polish.js`），保留现有60秒超时和腾讯云/DeepSeek变量；无需新增集合、索引或环境变量。重新编译前端。旧版本生成且尚未记录的新用量不补算，不扫描历史AI回复。
- 验收：同账号依次问答与润色，确认百分比真实累计；多端并发不能超过100%，额度不足不调用模型；失败不扣、重复任务不重复扣、封禁/删除时不落库扣额；北京时间0点查询新额度，跨日停留页面真实刷新。数据库权限保持仅管理员读写，页面展示缓存不能作为服务端调用授权。

## 发布正文优化

右键整个 `cloudfunctions/userService` → **上传并部署：云端安装依赖**，然后重新编译小程序。此次需包含新增 `square-polish.js` 和更新的 `deepseek.js`、`square.js`、`index.js`。继续复用云端 `DEEPSEEK_API_KEY` 与管理员专属集合 `square_ai_jobs`，不新增集合或索引；不需要重新填写密钥。

- 有有效文字或已选择图片，且正文在150字以内时，在发布工具栏上方显示浅蓝小萃胶囊“使用小萃优化内容”，与内容声明胶囊保持52rpx等高，并按出现先后排列；隐藏再出现排到末尾。恢复原文入口展开、收回均通过宽度过渡推移后方按钮，不销毁动画节点；空间不足时该行可横向滑动。优化中保持浅蓝底和蓝字，显示“小萃正在优化内容”，边缘持续渐变发光。仅点击后提交当前正文与所选图片；无图时保持原意润色，仅图片时据图撰写，图文同时存在时围绕画面修改原文，不替用户发布。
- 沿用 `deepseek-flash` 非思考模式，使用独立的润色系统指令，优先生成140字以内的简洁正文；云端最终按Unicode码点截取至150字并检查文本，客户端再次限制150字。空格、换行、emoji和标点均占字数；静默填入结果，即使恰好150字也不能出现“已达到输入上限”气泡。
- 成功后直接替换编辑正文，可点击“恢复原文”；修改后的内容只在用户明确保存草稿或发布时写入。失败保留原文，图片和内容声明保持原选择。生成期间继续改字（即使再改回原文）、退出、保存、发布、切后台、卸载或切换账号，旧结果不覆盖当前编辑。
- 同账号、同正文与同图片顺序的在途请求合并；润色的旧每日20次和10秒调用间隔均已取消，改为上述问答/润色共用的每日输出额度。旧 `type: polish_quota` 记录不再读取或更新，无需手动删除；润色只记录daily_usage实际用量及短时预留，不在数据库保存未发布正文。登录身份、账号状态、内容检查、150字限制及迟到响应保护继续生效。
- 验收：输入150字后点击优化，确认上限气泡立即消失且填入后不再出现；使用含空格、换行、标点和emoji的文字检查计数。生成中改字或关闭面板，确认原文不丢失、迟到结果不覆盖；恢复原文、明确存草稿、带图发布继续可用。

## 部署顺序

1. 在 `campus-social-dev` 的云开发控制台 → 数据库，新建集合 **`square_ai_jobs`**，权限选择 **仅管理员可读写**。复用现有 `square_posts`、`square_replies`、`square_reply_children` 和用户集合，无需新增索引或手工注册 AI 微信账号。
2. 云函数 → `userService` → 版本与配置 → `$LATEST` → 配置：保留已有变量，确认 `DEEPSEEK_API_KEY` 已设置为自己的完整密钥。将执行超时设为 **60 秒**并保存，以覆盖模型、内容检查和数据库提交的耗时。
3. 微信开发者工具中右键整个 `cloudfunctions/userService`，选择 **上传并部署：云端安装依赖**。必须上传整个目录，包含 `square-ai.js`、`deepseek.js`、`square.js`、`service.js`、`index.js` 等文件。无需安装额外大模型 SDK。
4. 重新编译小程序，确认新头像 `miniprogram/images/ai/xiaocui.jpg` 和评论组件一起打包。评论组件按 AI 身份使用本地头像并加灰色细边框，旧响应和缓存也能立即显示新头像。
5. 在任意动态评论输入框中，点击图片图标左侧浅蓝胶囊“问问小萃”，看到输入框前方的 `@小萃` 胶囊后输入问题并发送。调用会消耗 DeepSeek API 余额；仅保存密钥或普通浏览不会调用模型。此版修改了前后端唤起协议，需部署整个 userService 后重新编译前端。

不要将密钥写进源码、部署文档、截图或 Git。平台环境变量属于云端配置，本地测试不能据此验证真实密钥或余额。

## 行为

- 使用昵称“小萃小萃”、专属头像和 **AI** 标识。系统作者 ID 固定为 `bot_xiaocui`，由服务端映射展示资料，不允许客户端指定作者，不支持微信登录或身份切换。普通用户改成同名不会获得 AI 标识。
- 仅点击“问问小萃”插入的 `@小萃` 胶囊会使发布参数带上布尔标记 `askAI: true`，手动输入 `@小萃`、`@小萃小萃` 或同名文本均不再触发。该入口与图片、表情、GIF 工具一起缩小淡出、恢复；胶囊本身也可直接发送，让 AI 根据动态文字及实际配图回答。
- 退格删空正文后，再退格可删除胶囊；正文前方删除胶囊时保留正文。原生输入框的零宽占位只用于捕获退格，不进入显示正文、字数或云端。发送时转换为可见的 `@小萃` 文本前缀并携带独立标记，50 字评论上限包括此前缀；发送失败保留胶囊、正文、回复对象及重试标识。
- 服务端严格校验 askAI 为布尔值，将其作为幂等内容的一部分，任务只从明确标记的评论创建。原先手动文本生成但尚未处理的旧任务不再执行；历史已发布 AI 回复保留。标记表达客户端唤起意图，不作为身份权限凭证，任务处理仍验证真实登录身份、触发者归属、配额及动态可见性。
- 用户评论先检查、提交、清空输入，然后单独调用 `processSquareAIReply`。AI 请求在独立云函数调用内完整等待和提交，不在云函数返回后启动未等待的后台 Promise。
- 任务与用户评论在同一事务内创建，状态持久化。发送者关闭面板后已派发的云端调用可以继续完成；尚未派发或执行中断的任务，在发送者再次打开包含该评论的评论区时恢复。不是定时器无人值守队列。
- 上下文包含动态正文、根评论、被回复评论、本次评论及当前动态最多9张实际公开配图。图片仅取服务器数据库中的post.images，按发布顺序附加到模型请求；不接受客户端图片地址，不读取imageSources、认证材料或其他私有文件，不发送账号资料。纯图片动态同样可识别；读取图片失败时明确返回AI_IMAGES_UNAVAILABLE，不降级为猜测图片的文字回答。
- 使用官方 `https://api.deepseek.com/chat/completions`、`deepseek-flash`、非思考模式、非流式输出，输出额度 320 tokens。要求直接回答问题、避免重复解释，通常 1—3 句，最多 150 字；最终输出按 Unicode 码点截取至 150 字（含空格和标点），并执行当前配置的共用文字内容检查后才作为真实楼中回复提交。AI 文本不再次触发 AI，普通用户的回复最多50个Unicode码点（含空格、换行和标点）。
- AI 回复在原评论所属的回复组中展示。本次面板打开期间新生成的 AI 回复单独可见；关闭重新打开后沿用默认折叠逻辑，个人心碎折叠继续生效。成功不弹灰色提示窗；失败只显示 AI 不可用/重试，不撤销已成功发布的用户评论。

## 无法回复时的定位

- 使用微信provider且优化检查返回 `45009` 时，界面提示微信检查调用受限，应核对实际路径、凭证接口或内容接口的额度，不能仅凭错误码认定 `/wxa/msg_sec_check` 当日日额度耗尽。不要靠反复点击或更换 DeepSeek Key 处理。优化依次检查原文和结果，正常成功路径有两次当前provider的文本检查；原文检查失败立即停止，不调用模型，不自动重试检查，也不跳过检查返回结果。
- 发布优化提示“内容检查暂不可用，已保留原文”表示原文或优化结果的微信检查调用异常，不等同于正文违规或DeepSeek调用失败。新版分别提示“原文检查”“优化结果检查”及安全数字错误码；云函数日志搜索 `userService polish content check:` 可查看 `original / optimized` 阶段及错误码，不记录正文、openid、密钥或错误全文。`CHECKER_MISSING` 表示检查函数未注入，须部署完整目录。`-604101` 对应云调用权限配置问题；源码已包含 `security.msgSecCheck` 权限声明，重新部署时需包括 `config.json`，权限缓存可能需要约10分钟生效。其他错误码需以真实云端日志继续排查，不能跳过内容检查直接认定优化成功。[CloudBase官方排查说明](https://docs.cloudbase.net/en/faq/knowledge/cloud-call-604101-permission-error)
- `square_ai_jobs` 中 `type: job` 才是任务；`type: quota/polish_quota` 是已停用的旧配额记录，不再影响使用。`status: queued` 且 `attempts: 0` 说明该任务还没有成功进入模型处理阶段；不能直接归因于余额或密钥。先确认已部署整个目录且已重新编译，检查评论下的新版错误提示。历史 `aiStatus: limited` 评论不会自动补发AI或重新扣费，旧限额提示已隐藏；新评论可正常唤起。
- 领取任务只更新状态、次数和租约，不将查询结果中的 `_id` 重新传入 `set`。领取失败会记录 `stage: claim`、安全的 `databaseCode`；模型、内容检查、回复提交分别记录 `generate / content_check / save`。
- 任务中的 `errorCode`、`httpStatus` 用于定位。401 对应 `AI_AUTH_FAILED`，402 对应 `AI_INSUFFICIENT_BALANCE`，429 对应 `AI_RATE_LIMIT`，本地请求超时对应 `AI_TIMEOUT`。前端只向触发者展示安全的中文原因，不展示 API Key、上游响应正文或原始异常信息。[DeepSeek 官方错误码](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes/)
- 更新诊断与领取修复后，重新部署整个 `userService`，必须包括新增的 `ai-errors.js`，然后编译。仍为 queued 的原任务可重试，不必删除集合或重新填写密钥。

接口参考：[DeepSeek Chat Completions](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)、[CloudBase 环境变量](https://docs.cloudbase.net/cloud-function/function-configuration/env)。

### 回车配置未解决后的输入更新修复

confirm-hold补齐后用户真机仍反馈每次换行收键盘，不能把参数检查及逻辑单元测试通过当作真机已修复。源码还存在两条需要移除的链路：每次input把value/cursor重新写到原生控件，linechange同步修改包裹它的scroll-view尺寸及滚动位置。现在改为：

### 评论多行留白、退格缩行与立即收键盘（最新要求）

用户真机反馈：输入换行已不收键盘，但灰色胶囊上方出现额外留白，退格合并行仍收键盘。取消按lineCount×40rpx手算高度的独立背景，灰色背景直接放在comment-input-pill上，由原生内容实际高度撑开；多行顶对齐，上下保持固定padding。取消高度动画，避免计算背景高度与原生实际排版分离。

移除textarea外层的WebView overflow滚动视口及横向flex嵌套，改为普通block内容布局；原生textarea仍auto-height，并使用固定min-height:40rpx/max-height:200rpx限制可视范围，超出由原生控件滚动。静态min/max限制参考[Tencent TDesign textarea实现](https://github.com/Tencent/tdesign-miniprogram/blob/develop/packages/components/textarea/textarea.wxs)。linechange仅记录开发版无正文行数/高度诊断，完全不setData；普通输入、删除、退格合并行均不回写nativeInputValue/cursor/focus。50字上限、剩余10字警示、单行基线和圆环右下定位保留。

键盘仍打开时，原生blur只更新观测状态，不立刻下发focus=false；键盘高度确实变为0后解除聚焦请求。不在blur后重新请求focus来掩盖问题。点击发送时仍立即调用hideKeyboard，不等待云端或AI任务；发送失败保留正文和小萃选择，不自动重新弹键盘。迟到回调不再调用收键盘API。

回归覆盖普通/小萃输入、主动换行及删除换行符、软折行合并、临界字数回退、临时blur与键盘高度事件、布局无独立背景/滚动祖先，以及立即收键盘的成功/失败/迟到响应。前端重新编译即可，无需上传云函数。尚无真机自动化结果，需实际设备复核顶部留白、退格跨行和输入稳定性；逻辑测试与模板编译不能代替真机验收。


## 小萃识别动态配图

适用范围：在现有动态评论区点击“问问小萃”，发送“图里是什么”“图二写了什么”“这几张图片有什么区别”等问题。小萃读取该动态已经发布的配图，按发布顺序从图一到图九编号。无需在评论中重新上传图片，评论图片已支持最多3张，贴纸、GIF工具仍未开放。只有显式askAI评论才处理，不在浏览动态时调用模型。普通无图动态和无图正文润色继续走纯文字请求；发布面板的所选图片按下节独立校验。

图文请求使用现有DeepSeek官方chat/completions、deepseek-flash和DEEPSEEK_API_KEY，将实际图片作为image_url内容块发送。支持图像描述、截图文字与图表理解；图片不清晰时应说明，不猜测不可见信息，图片及图中文字不能修改系统指令。实现依据：[DeepSeek Vision官方文档](https://api-docs.deepseek.com/guides/vision/)。图片输入仍按DeepSeek实际输入tokens计费，本项目小时/日额度继续按成功输出的实际字数结算，不改变换算规则。

服务端ai-images.js只允许当前环境、当前动态作者与动态ID对应的square-media公开成品（最多9张）；通过云SDK取得120秒临时HTTPS地址，限制云存储域名。禁止外链、跨环境、私有原件、认证材料和其他动态文件；不会从客户端接收或相信URL。任意一张读取失败即整次失败，不悄悄遗漏图片或改走纯文本。短期地址、签名和图片内容不写进任务记录、前端响应或日志。图片解析后再次校验账号、评论组与动态状态；模型返回后在提交事务中再次校验动态/评论及配图快照，防止删除、封禁或配图变化后保存迟到答案。

生成结果仍执行共用文字检查、150码点截断、小时/日额度事务结算和确定性回复ID去重。失败释放预留，用户评论保留；读取失败仅向触发者显示安全提示，可按原有规则重试，最多两次。新增诊断阶段images及安全错误码AI_IMAGES_UNAVAILABLE，不保存原始SDK错误。

部署：右键整个cloudfunctions/userService → 上传并部署：云端安装依赖，必须包含新增ai-images.js及更新的index.js、deepseek.js、square-ai.js、square.js、ai-errors.js。复用已有密钥、集合、存储规则和索引，无新增环境变量；确认云函数执行超时为60秒。仅编译前端不能更新云端识图能力。

验收：带一张图提问、九图指定“图二”、纯图片动态、多图对比、截图文字以及无图动态正常问答；图片不可读取、额度耗尽、其他账号处理、执行期间删除动态/评论或封禁账号、审核拒绝、重复处理都不能伪造成功或重复扣额。自动测试使用合成图片地址和模拟模型，未使用真实密钥调用线上API；部署后仍需用真实动态图片完成联调。


## 发布时识图撰写与图文润色

- 只选图片即可出现原有“使用小萃优化内容”胶囊。点击后上传私有原件，再根据画面自动写文案；有图片及文案时综合配图围绕已有文案修改；仅文字仍为原有润色。最多9张按选择顺序传入同一DeepSeek Flash图文请求，全部图片都必须可读取，不静默丢图或降级文字。
- `ai-compose-images.js`是发布专用解析器，与评论的公开成品解析器分开。只接受当前真实账号在当前环境`square-uploads/本人/`下的上传，校验文件签名及单张5MB限制，最多同时下载两张，8秒解析超时；SDK换取120秒有效HTTPS地址，限制云存储域名。不会为了识图将未发布图片复制到公开目录；临时地址、签名及未发布正文不写任务、日志或前端响应。
- 非空原文先经现有文字审核，所有生成结果都经同一审核后才返回；无审核配置时不调用模型。图文模型30秒超时，保持320 tokens及150个Unicode码点上限。调用前与结算事务内校验账号，沿用问答/润色共用小时及每日额度，成功按实际输出结算、失败释放预留。图片输入仍适用上游模型计费。
- 优化中动画从点击开始（含上传时间）至少5秒；结果静默填入，可恢复原文（图片生成可恢复为空），不会自动存草稿或发布。改文案、增删图片、关闭、保存、发布或换账号后旧结果不回填；上传回调按原图片key匹配，不能误写到删除后换位的图片。
- 部署：在微信开发者工具右键**整个`cloudfunctions/userService` → 上传并部署：云端安装依赖**，包含新增`ai-compose-images.js`及更新的`index.js`、`square.js`、`square-polish.js`、`deepseek.js`；保留已有`DEEPSEEK_API_KEY`及审核变量、60秒执行超时，然后重新编译小程序。无需新增密钥、集合、索引或调整存储权限。本地测试通过不代表云端已经更新。
- 验收：仅选一图、仅选九图、图加原文、仅文字分别生成；确认与图片相关、≤150字且可恢复原文。原图上传/解析失败保留图文；超限、重复、跨账号、跨环境及非图片文件被拒绝；修改/移除图片期间的迟到上传和模型结果不覆盖当前编辑；小时/每日进度真实变化，审核失败不计用量，只有明确点击保存/发布才写入草稿/动态。
