# 真实关注与关注时间线

## 部署

1. 在当前小程序云环境数据库新建 **`user_follows`** 集合，权限设置为 **仅管理员可读写**。自定义规则可直接使用同目录 `user-follows.rules.json`，即 `{"read":false,"write":false}`。小程序只能通过云函数读写关系。
2. 确认已有 `square_posts` 的 `posts_square_feed` 普通复合索引：`scope` 升序、`status` 升序、`sortKey` 降序。关系使用确定性文档主键，不需要新的关系查询索引。
3. 上传并部署整个 **`cloudfunctions/userService`（云端安装依赖）**，包含新增 `square-follows.js`，随后重新编译前端。无需新增环境变量或存储权限；保留现有 AI 超时及审核配置。

此前只有本地关注演示，没有历史真实关系需要迁移。新关系及统计从真实操作开始累计。不要在客户端自行开放数据库写入、手工伪造关系或改写计数。公开 ID 沿用 `account_ids` 的既有补齐流程。

## 行为

- 普通未认证登录账号可关注他人，不能关注自己。服务端从可信会话取得操作人，公开 ID 解析目标；事务中重新校验双方状态，再同时保存关系和双方统计。重复相同操作不重复计数，失败回滚，客户端先显示乐观状态，只有云端确认后才更新真实关系基底，失败回退并提示。
- 他人主页通栏关注按钮在点击后立即平滑拆分为“已关注 / 私信”，后台保存；取关需要确认，点击红色取关后立即恢复通栏。首页头像菜单、详情页和主页取关均使用同一底部确认组件，展示目标头像/用户名、红色取关及独立取消按钮；取消不提交，确认后立即退出弹窗；后台失败恢复已确认关系和统计并提示，不自动重开旧弹窗，离页或换账号取消待确认。私信只保留入口并提示暂未开放，不创建虚假会话。
- 首页头像菜单、加号转勾动画、详情关注按钮、个人主页和侧栏统计使用同一真实状态。关注和粉丝数首次未知显示破折号，后台更新保留已有真实内容。
- 动态广场 → 关注展示已关注作者的普通动态及引用，包含关注前已发布的公开内容，按发布时间倒序。自己的帖子不会自动混入；取消关注后移除该作者，不能因旧分页返回而恢复。校园圈的关注入口仍未开放。
- 推荐与关注缓存隔离；关注支持现有 Cui 下拉刷新和游标加载更多。分页游标按唯一 `sortKey`，插入新帖子不会导致旧页重复跳过。服务端每次最多检查 400 条公开时间线并批量验证关系；关注稀疏时可出现空的一页，但会保留真实“加载更多关注动态”入口继续向前查找，不限制关注人数或伪报已到末尾。此实现不维护写入扇出的副本，未来大规模流量可替换为专门的时间线索引。
- 关系缓存按登录会话隔离、读请求合并、写入按同会话串行、同目标合并最新意图。共享pending投影在三个入口立即显示，已知统计同步投影，未知统计不猜测。旧读取和旧写入不能反弹最新选择；失败回退确认值并提示，已隐藏页面不回写视图，不误报持久化成功。退出或换账号清理状态。

## 验收

1. A、B 均使用普通未认证账号，A 从动态头像菜单进入 B 主页；A 的编辑/置顶等本人操作不出现在 B 主页。
2. A 点击关注：按钮立即显示“已关注 / 私信”，不等待云端读取或保存；确认取关同样立即变化，后台串行保存最终选择。B 的粉丝数、A 的关注数各加一；返回首页再进入、重新启动后关系仍正确。
3. 在 B 的主页点击私信，只显示暂未开放提示。点击已关注并取消确认，关系不变；确认取关后按钮及已知统计立即更新，后台成功后双方真实统计各减一；失败回退原关系及统计。重复请求不会负数或多扣。
4. 首页保留原加号变勾后淡出的动效。主页关注后返回首页无需再次点击就能显示真实关系，取关面板的取消与确认正常工作。详情按钮也应同步。
5. B 发布文字、图片和引用动态；A 关注页可读取并正常点赞、评论、引用、预览图片，推荐页不受切换影响。A 取关 B 后 B 的动态从关注页移除，推荐页和 B 主页仍正常可见。
6. 多页滚动、插入新动态、下拉刷新、稀疏关注及删除动态时无重复或漏页。加载中切换推荐/关注、退出/换账号，旧结果不得覆盖新列表或旧关注状态。
7. 网络失败保留真实缓存并显示错误；服务端禁止自己关注自己、禁用目标或伪造操作人。未登录关注页只显示登录提示，不展示上一账号内容。

自动化覆盖事务幂等、并发、回滚、身份校验、分页、稀疏扫描、状态缓存、会话隔离及主页按钮流程；真机验收仍需在完成以上云端部署后执行。

最新的即时响应优化只涉及前端（共享关系投影、后台队列及三个入口），已部署真实关注云端的环境重新编译前端即可。验证慢网下关注→取关→关注、写入失败、多个作者并发点击及切账号：界面始终对应最后一次选择，旧结果不能反弹，后台最终保存一致。
